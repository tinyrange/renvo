Goroutines and channels without putting a scheduler in the compiler

Implement issue #366 as a typed frontend feature that lowers to a small, pluggable execution ABI. Renvo owns Go semantics and deterministic lowering; a target-provided handler owns stacks, scheduling, blocking, wakeups, and channel storage.

Based on the current main architecture: compact checked packages, whole-program source lowering, direct-emitter backends, bounded arenas, and no general garbage collector.

Recommended architecture Frontend-first Backend-neutral Single-threaded concurrency v1 Dedicated thread-state register One implementation PR No unit-v1 break

Recommendation

Lower concurrency before the backend boundary. Add real parser/checker support for go, channel types and operations, channel range, and select. Preserve typed operation metadata through package linking, then rewrite those constructs into ordinary Renvo subset code that calls renvo.dev/x/runtime. Existing architecture backends should see direct calls, structs, slices, pointers, switches, and scalar channel handles—not new machine-level channel instructions.

Compiler owns

Typing, evaluation order, temporary storage, thunk/context generation, nil and close checks, receive comma-ok, select case setup, and diagnostics.

Handler owns

Runnable stacks, queueing, blocking, wakeups, channel buffers, atomic selection, fairness policy, and target integration.

Backends own

One narrow ABI addition: a reserved logical register points at the active Renvo thread-state structure. Native targets use a non-allocatable physical register; stack machines and portable reference outputs provide the equivalent reserved execution-context slot.

Do not interpret “goroutine” as “parallel OS thread” in v1. The initial contract must require a handler to serialize execution of Renvo code, typically by switching stacks cooperatively on one core. Panic/recover and other execution-local state will already live behind the dedicated thread-state register, but the allocator, print mirroring, and application data are not generally synchronization-safe. Parallel execution is a later runtime project, not an accidental promise of this compiler change.

Policy gate before implementation

The current AGENTS.md describes goroutines, channels, and select as a closed exclusion. The implementation PR may change that rule, but only as far as required to permit this syntax to be parsed, checked, and lowered through the handler ABI. It should not broadly redefine the language roadmap or enlarge the direct backend source subset.

  1. Permit goroutines, channels, and select only as frontend syntax lowered through the handler runtime.
  2. Keep them out of the direct backend source subset; high-level constructs must be gone before the compact backend unit is emitted.
  3. State that v1 provides concurrency but not parallel execution.
  4. Retain generics and cgo as excluded; no unrelated scope expansion.
This gate is mandatory. Keep the edit surgical: replace only the three exclusions needed by issue #366 and add the lowering boundary. Existing backend edit restrictions, syscall limits, test rules, resource gates, and all unrelated scope rules remain intact.

Pre-merge hardening addendum: the implementation also supplies the Go-shaped core sync primitives (Mutex, RWMutex, WaitGroup, Once, and Cond) on top of the same serialized handler, plus persistent lowering and channel-state fuzz targets. This does not authorize parallel execution, a new backend synchronization ABI, or any other language/runtime expansion.

Explicit non-goals for the first merge

  • Implementing a production RTOS or a work-stealing scheduler.
  • Matching the Go runtime’s scheduler heuristics, stack growth, preemption, or randomized implementation details.
  • Making arbitrary existing Renvo code data-race safe.
  • Garbage-collecting channel headers, channel buffers, or completed goroutine contexts. Under the current bounded-arena model they remain live until process termination.
  • Adding goroutine syntax to the intentionally smaller direct backend test language.

Although an RTOS is not a v1 deliverable, the thread-state register, task trampoline, and handler boundary must be implementable on bare-metal microcontrollers without hosted TLS, dynamic linking, or operating-system syscalls.

Why typed metadata, not a text-only rewrite

Channel lowering must know the exact element type and size, named-type identity, direction, receive arity, select scope, and whether an expression is evaluated for side effects. Re-discovering those facts from linked text would repeat the fragility that the checker already solved. Add a compact, linker-only concurrency table to internal/unit.Program and its RVFC cache encoding; omit it from CoreProgram after lowering.

No public unit schema change is needed. The canonical backend unit should contain the generated direct-subset program only. The metadata is an internal frontend-cache contract and can be version-bumped independently when its layout changes.

Portable goroutine entry dispatch

Treat the issue’s entry uintptr as an opaque whole-program entry ID, not necessarily a native program counter. Assign deterministic IDs after linking and generate a dispatcher. This avoids unsafe function-pointer conversion and works on Wasm, VM, C89, and unusual Harvard-style targets. 

// Conceptual generated code for: go consume(source(), value())
type __renvo_go_context_3 struct {
    call func(int, string)
    arg0 int
    arg1 string
}

func __renvo_go_entry_3(raw uintptr) {
    context := (*__renvo_go_context_3)(unsafe.Pointer(raw))
    context.call(context.arg0, context.arg1)
}

// Callee and arguments are evaluated now, left to right.
context := &__renvo_go_context_3{consume, source(), value()}
renvo_runtime_Spawn(3, uintptr(unsafe.Pointer(context)))

func renvo_runtime_Call(entry uintptr, context uintptr) {
    switch entry {
    case 3:
        __renvo_go_entry_3(context)
    // deterministic arms for all other go sites
    default:
        panic("runtime: invalid goroutine entry")
    }
}

Contexts use persistent arena allocation because the spawned call can outlive the parent stack. The generated code must not reclaim or stack-allocate them until a future ownership mechanism proves that safe.

Dedicated thread-state register

Follow Go’s execution-state model: every running Renvo stack has a ThreadState, and one reserved logical register always points to the active structure. The register is not available to ordinary value allocation. Function calls preserve it, program entry initializes it for the main stack, and runtime.Call installs a fresh state for a spawned stack before entering the generated dispatcher. A scheduler context switch naturally saves and restores the register with the rest of the callee-saved machine context. 

// Internal compiler/runtime ABI; not a public application struct.
type ThreadState struct {
    Self uintptr

    PanicValue uintptr
    PanicType uintptr
    PanicID uintptr
    PanicNextID uintptr
    PanicPrevious uintptr
    PanicDeferPending uintptr
    PanicRecovered uintptr

    SchedulerContext uintptr // opaque handler/RTOS task identity
    Flags uintptr
}

Move the existing panic/recover BSS fields behind this pointer in v1 rather than adding a register that initially points at shared state. Keep the layout versioned and compiler-internal so later work can add stack bounds, cancellation, tracing, allocator ownership, or RTOS task metadata without exposing it as source API.

One ABI, target-appropriate representation. Native register backends reserve a callee-saved physical register. RTG exposes the thread-state register in its target contract. VM uses a reserved VM register, and Wasm uses a reserved mutable execution-context slot. Portable C89 and other toolchain-mediated reference backends thread an explicit hidden state value when a physical register cannot be promised portably. These are equivalent implementations of the same ABI, not a reason to omit a target.

This is intentionally useful beyond hosted systems. A future microcontroller RTOS handler can allocate one ThreadState beside each task control block, initialize the reserved register in the task trampoline, and let the RTOS context switch preserve it. Building that RTOS and parallelizing execution are outside v1; making the ABI compatible with them is part of v1.

Channel representation

A lowered channel value is one opaque word. The checker continues to distinguish chan T, <-chan T, chan<- T, and named channel types. Generated typed wrappers stage values in addressable temporaries and pass byte addresses plus statically computed element sizes to the handler. This preserves structs, arrays, strings, slices, interfaces, and other multiword values without pretending they fit in one uintptr.

Required handler contract

  • Spawn schedules the entry; it must not assume Entry is a native address. The handler invokes it through runtime.Call.
  • The handler copies exactly elementSize bytes while a send/receive/select call is active. It never retains the temporary value pointer after the operation completes.
  • A blocking operation may suspend the current Renvo stack and run another, but v1 must never execute two Renvo stacks simultaneously.
  • Closing marks the channel closed and wakes waiters; it does not free an aliased channel header. Resources remain valid for later receives and required panic checks.
  • Select chooses exactly one ready case atomically. Fairness is implementation-defined but starvation tests should reject a permanently first-case policy.
  • Nil channel sends/receives block forever, nil cases are disabled in select, and closing nil is invalid.
  • EnableGoroutines may be called once. A nil handler, second registration, or concurrency operation before registration enters the normal recoverable panic path with a useful message.

Bundling and package identity

Add x/runtime to both embedded bundle declarations and the bundled module root listing. Calls that require compiler treatment must be selected by the semantic import path renvo.dev/x/runtime plus declaration name, then mapped to reserved aliases. Never specialize an arbitrary user function merely because it has the same spelling.

Implementation phases

0

Policy and executable ABI spike

  • Make the minimum AGENTS.md edit needed to permit frontend parsing/checking/lowering of the three syntax families; preserve every unrelated rule and keep direct backend syntax excluded.
  • Add a scratch probe under ignored sandbox/ for the proposed handler interface, unsafe value buffers, result shapes, and generated dispatcher.
  • Define the logical thread-state register contract and map it across every backend family, including native 64/32-bit, Wasm, VM, LLVM, RTG, C89, and microcontroller object targets.
  • Prove the dispatcher and thread-state access path on linux/amd64, one 32-bit target, Wasm, VM, and one RTG/C path before freezing public names.
  • Document the serialized-execution rule and channel lifetime policy.

Exit: API signatures compile through host and self-hosted frontends; no architecture requires a raw function pointer; every backend has a credible thread-state mapping.

1

Syntax and checked type model

  • Add TypeChan with element span and send/receive direction.
  • Parse select blocks and communication clauses explicitly instead of treating them as switch cases or generic statements.
  • Model send statements, unary receives, receive assignments, channel range, and goroutine calls.
  • Replace the blanket exclusions with precise validation and retain structured errors for invalid operations.
  • Teach hover/completion/navigation to render channel types and scope select receive variables.

Exit: checker tests cover valid/invalid constructs without lowering or backend execution.

2

Concurrency metadata and package-cache transport

  • Add compact channel-type and operation-site records to the checked package and internal/unit.Program.
  • Emit token spans for callee/arguments, send/receive values, channel operands, select clauses, and element types.
  • Version and extend the in-process frontend cache; reject stale encodings instead of silently dropping operation metadata.
  • Remap metadata through package aliasing, text edits, artifact caching, and package merging.
  • Assert that CoreProgramFrom contains no high-level concurrency metadata.

Exit: cached and uncached frontend paths produce identical metadata and linked text.

3

Channel lowering, excluding select

  • Rewrite channel types to opaque-word representations while preserving named-type identity where observable.
  • Generate typed create/send/receive wrappers and addressable value temporaries.
  • Lower close, len, cap, nil comparison, direction erasure, and channel range.
  • Inject the runtime dependency when concurrency syntax is used, even if the source package imports no runtime package directly.
  • Run this pass before function-value lowering and after semantic package identities are known.

Exit: buffered channel programs run end-to-end on all existing executable targets with a deterministic test handler.

4

Thread state, goroutine thunks, and dispatcher lowering

  • Reserve the target’s thread-state register/slot so ordinary code generation can never allocate it.
  • Move panic/recover state from global BSS into the versioned ThreadState layout.
  • Initialize main’s state at program entry; make runtime.Call install and restore a fresh state around a spawned entry.
  • Require normal calls, indirect calls, foreign-call adapters, and RTG-generated calls to preserve the thread-state ABI.
  • Generate one context type and thunk per distinct go site.
  • Stage callee and arguments in strict Go evaluation order before Spawn.
  • Use existing function-value/closure lowering for dynamic callees, bound methods, and captured values.
  • Assign deterministic whole-program entry IDs and generate the runtime.Call switch.
  • Guard use before EnableGoroutines with a clear recoverable panic.

Exit: named calls, method calls, function values, closure calls, loop sites, and side-effecting arguments run exactly once; independent goroutines have distinct panic state; self-host output is stable.

5

Select lowering

  • Stage case operands and send values once, in source order, before asking the handler to select.
  • Build a temporary descriptor slice with destination pointers and receive-ok pointers.
  • Dispatch the returned case index through an ordinary switch and preserve case-local scope and break behavior.
  • Handle default, empty select, nil cases, closed receives, and send-on-closed panic status.
  • Add fairness and atomicity requirements to the handler conformance tests.

Exit: select programs cover mixed send/receive cases, default/no-default, nil/closed channels, and side effects.

6

Reference scheduler and target qualification

  • Provide one small handler with independent stacks and cooperative scheduling, or bind an existing target scheduler through the same contract.
  • Run unbuffered send/receive, blocking select, close wakeups, nested spawning, and many-goroutine stress cases.
  • Verify context switching preserves the dedicated thread-state register and keeps panic/recover state isolated.
  • Verify clean shutdown: main return retains Go behavior, while blocked goroutines do not keep the process alive.
  • Document how a board package registers its handler and how a future microcontroller RTOS task trampoline installs thread state, without implementing the RTOS in v1.

Exit: the issue’s feature is demonstrably useful, not merely accepted syntax.

7

Self-host, performance, and documentation closure

  • Compare host and self-hosted canonical units for the full concurrency corpus.
  • Run normal preflight plus focused frontend/backend checks; reserve ./tools/check full for the merge queue unless explicitly requested.
  • Measure unused-feature compiler size/RSS/time and per-site generated code/context overhead.
  • Update public API docs, language scope, target capability docs, and examples.
  • Remove obsolete excluded-feature negative fixtures only after replacement diagnostics and positive coverage land.

Exit: all gates pass without weakened budgets and the feature is documented end to end.

Testing strategy

Layer 1: parser and checker

Add table-driven unit tests for every syntax/type rule, including directional assignment, select scoping, invalid receive/send, duplicate default, invalid go operand, builtin arity, and exact diagnostic source tokens.

Layer 2: lowering shape

Inspect linked text and compact units. Assert deterministic site IDs, no remaining go/chan/select constructs, no duplicate evaluation, no raw imported runtime aliases, and cached/uncached parity.

Layer 3: frontend regressions

Create focused modules under frontend_tests/regressions/. Positive expectations are checked in with go run ./cmd/renvoexpect -write. Cover values crossing all important storage boundaries:

  • scalar, string, slice, interface, array, and struct channel elements;
  • globals, locals, function arguments/results, struct fields, and closure captures;
  • named and directional channel types across packages;
  • direct calls, method values, function values, closures, and side-effecting goroutine arguments;
  • buffered, unbuffered, nil, and closed channel state;
  • receive comma-ok, range, default select, empty select, and mixed select cases;
  • panic/recover for send/close errors and deferred work in a goroutine.

Layer 4: handler conformance

Define a reusable suite that every handler can run. It should verify byte-copy integrity, FIFO buffering, rendezvous, waiter wakeup, closed-channel draining, nil behavior, atomic select, eventual fairness, nested spawn, stack independence, and serialized Renvo execution.

Layer 5: portability and self-hosting

  • Compile the same corpus through native 64-bit, native 32-bit, Wasm, VM, and prepared RTG/C backends.
  • For every implementation, verify thread-state identity through direct calls, indirect calls, deep recursion, panic/recover, foreign adapters, and a synthetic stack switch.
  • Inspect native disassembly to prove the chosen physical register is reserved and preserved; inspect Wasm/VM/C/LLVM output for the documented equivalent state path.
  • Compare stage0 and self-hosted linked units byte-for-byte.
  • Build a standalone bundled compiler outside the checkout and compile a program importing renvo.dev/x/runtime.
  • Keep direct backend regressions limited to any ordinary subset miscompile discovered during lowering; each new backend reproducer prints only PASS\n.

Performance and resource gates

Concurrency support must not charge programs that do not use it. The linker should discover an empty operation table and return without generating runtime helpers or pulling x/runtime into the output.

Compiler budgets

  • No regression to existing 50 ms/100 ms backend gates.
  • No increase beyond the established stripped compiler and RSS ceilings.
  • Bound metadata linearly by source sites; preallocate before transient per-function work.
  • Discard typed concurrency metadata immediately after lowering.

Generated program budgets

  • One dispatcher arm and one small thunk/context type per go site.
  • Deduplicate typed channel wrappers by canonical element type.
  • No handler/runtime code linked when unused.
  • Measure context bytes, spawn latency, channel throughput, and select latency.
  • Measure register-pressure and code-size impact from reserving the thread-state register, including programs that never use concurrency.

Add benchmark programs under ignored sandbox/ first. Promote only stable regression coverage into the repository’s existing harness; do not edit or loosen backend/main_test.go or performance thresholds.

Deliver as one atomic PR

One feature branch, one draft PR, one merge. All phases in this document are internal implementation checkpoints, not separately merged pull requests. Keep the PR draft while the syntax, runtime contract, thread-state ABI, lowering, reference handler, tests, and documentation are incomplete. Mark it ready only when the complete vertical slice works and every required target still builds.

Definition of done

  • AGENTS.md contains only the narrow exception needed to permit frontend goroutine/channel/select syntax and lowering; unrelated restrictions are unchanged.
  • The public runtime contract is documented and bundled offline.
  • Every implementation provides the thread-state register/slot ABI, and native backends demonstrably reserve their chosen physical register.
  • Main and spawned stacks receive distinct thread states; panic/recover state is no longer shared BSS.
  • All channel directions and operations follow Go typing and evaluation order.
  • Generated goroutine contexts remain valid after the parent returns.
  • Entry IDs and generated helper ordering are deterministic.
  • No high-level concurrency syntax or metadata crosses into CoreProgram.
  • At least one handler passes unbuffered, blocking select, close, nil, and stress conformance tests.
  • The bundled core sync primitives pass host race tests and host/self-host Renvo contention regressions.
  • Persistent model-based runtime and grammar-based lowering fuzz targets complete without crashes or invariant failures.
  • Concurrent execution is serialized in v1, with thread state switching correctly; parallel execution is not advertised.
  • The ABI documents a no-hosted-TLS path suitable for a future microcontroller RTOS task trampoline.
  • Host, cached, self-hosted, and standalone bundled frontend paths agree.
  • IDE hover/completion/navigation understand channel types and select bindings.
  • ./tools/check preflight and focused concurrency suites pass; merge-queue full validation passes without relaxed gates.
  • README, guide, backend subset docs, command help, runtime API docs, and examples tell one consistent story.
