North-star roadmap · 15 August 2026

Renvo C → Linux

The deliberately unreasonable destination: point Kbuild at a tiny, self-hostable Renvo compiler, compile every target C translation unit, link an upstream x86_64 kernel, and boot it under QEMU—without turning Renvo into a memory-hungry imitation of Clang.

North star: boot first target: x86_64 tinyconfig dialect: GNU C11 hard gate: < 2,000,000-byte compiler foundation: PR #381

01 · Define the win

A bootable kernel, with honest boundaries.

Here, “Linux” means the upstream Linux kernel, not a userspace distribution. The first finish line is intentionally narrow enough to measure and broad enough to prove the compiler: one pinned upstream commit, x86_64, tinyconfig, and a deterministic QEMU boot.

Renvo compiles the target C

Every selected kernel .c translation unit is preprocessed, checked, lowered, and emitted by Renvo. No per-file fallback to GCC or Clang.

The source tree stays upstream

No semantic source patches, generated rewrites, or hardcoded file results. A small compiler wrapper and Kbuild configuration are acceptable.

Existing tools may finish the image

Initially, GNU or LLVM tools may assemble .S, archive objects, apply linker scripts, and create the boot image. Inline assembly inside C remains Renvo's responsibility.

The result boots and reports success

vmlinux passes structural checks and reaches a fixed early-console or initramfs marker under QEMU before a controlled shutdown.

Why x86_64 first? Renvo already has a hidden linux-kernel/amd64 target that emits ELF64 relocatable module objects, imports kernel symbols, and understands kernel metadata. That is a real head start. The full-kernel path must become a separate general -c object mode; it must not smuggle module wrappers or .modinfo into ordinary kernel objects.
First concrete checkpoint: hosted Hello World. Before touching Kbuild, compile an ordinary C file through a real installed system header into a conventional ELF relocatable object. The host C driver is used only to supply startup objects, libc, and the system linker; Renvo is the sole compiler for hello.c. 
#include <stdio.h>
int main(void) { puts("Hello, world!"); return 0; }

renvo cc -c hello.c -o hello.o
cc hello.o -o hello
./hello
# stdout: Hello, world!
The object must expose main, leave puts undefined, carry standard x86_64 SysV relocations, and require no Renvo runtime or source-specific linker trick.
02 · Architecture

Share the compiler. Keep the semantics honest.

The current C-to-Go-shaped adapter is the right bootstrap seam. It proves source discovery, diagnostics, mixed-language symbols, and reuse of the package/link/backend pipeline. It is not the final representation for unions, bitfields, C aliasing, volatile accesses, section attributes, or GNU inline assembly.

C bytesone mapped or loaded source buffer
Streaming CPPinclude stack, compact macros, bounded expansion
C parserindexed declarations and expressions, arena lifetime
Checked coretypes, layout, constants, control flow, source spans
Renvo unitshared symbols, linker, reachability, canonical ops
amd64 emittershared machine operations and ABI
ELF + system toolshost link first; Kbuild asm/archive/link next
C-specific shared with Go external initially
Share
Driver, filesystems, diagnostics, package graph, source positions, symbol identity, canonical unit, reachability, cache, ABI primitives, instruction emitter, and ELF machinery.
Keep C-specific
Preprocessing, declarator parsing, C conversions, compatibility rules, aggregate layout policy, lvalue rules, C linkage, GNU attributes, builtins, and inline-asm constraints.
Evolve safely
Continue translating the scalar overlap through Go-shaped source. Add typed canonical operations only when a real C semantic cannot be represented exactly. Move the Go frontend onto those operations opportunistically, with byte-for-byte unit gates and CPU/memory regression telemetry.
Never globalize
Compile one translation unit to one relocatable object, release its arena, and let Kbuild link objects. Never retain a kernel-wide AST, token stream, or type graph.
03 · Milestones

Every phase ends in an artifact.

Progress is a ladder, not a percentage. Each rung produces something inspectable and locks in a regression before the next language feature is added.

M0
Hosted object

Compile and system-link ordinary C Hello World

Build the smallest complete compiler-driver slice before introducing Kbuild: read #include <stdio.h> through the installed system include paths, compile a normal main that calls puts, emit an ordinary Linux/x86_64 ELF ET_REL object, and link it with the system C driver.

  • Add the minimal renvo cc -c input.c -o output.o persona, include search, target predefined macros, and diagnostics needed by the real header.
  • Lower C entry/call boundaries to the x86_64 SysV ABI; emit an exported main, undefined puts, string data, and standard relocations.
  • Inspect the result with readelf, link with cc hello.o -o hello, run it, and check exactly Hello, world!\n.
  • Do not special-case the source filename, stdio.h, puts, the output bytes, or host library paths.
A checked acceptance test produces hello.o; the system linker and libc accept it; the executable prints the expected line.
M1
Kbuild handshake

Turn the hosted slice into a truthful kernel driver

Pin an upstream kernel commit/config, capture its real compiler invocations, then extend the M0 driver without disturbing Renvo's package-oriented CLI: -E, -x c, kernel include paths, defines, forced includes, dependency files, target flags, response files, version queries, and correct exit codes for option probes.

  • Accept harmless warning/optimization flags explicitly; reject unsupported semantic flags.
  • Make cc-option probes truthful—unknown flags must never silently succeed.
  • Keep host tools on HOSTCC; only target CC points to Renvo.
  • Add a read-only census over Kbuild .cmd files and classify syntax, builtins, flags, sections, relocations, CPU, RSS, and object sizes.
Complete · Linux 6.12.99 x86_64 tinyconfig reaches scripts/mod/devicetable-offsets.c:5:1 after Renvo emits Kbuild's first ET_REL object and dependency rule.
M2
Preprocessor

Generalize the hosted slice into a serious preprocessor

Extend the behavior proven by the real stdio.h path to all translation phases needed by GNU C11: line splicing, comments, object/function/variadic macros, rescanning, hide sets, #, ##, #include, conditionals, defined, #line, include guards, #pragma once, and kernel/compiler predefined macros.

  • Represent replacement lists as compact token spans and intern macro names once.
  • Use an include stack and expansion stack; do not materialize a giant preprocessed file.
  • Retain spelling/source maps only where diagnostics or stringizing need them.
Complete · the checked corpus matches GCC's token stream on host and stage3, and -E preprocesses the complete pinned scripts/mod/devicetable-offsets.c closure with transitive dependencies.
M3
ISO C core

Finish the C11 semantic foundation

Add the parts that cannot be safely faked as Go: typedef namespaces, full declarators, structs/unions/enums, bitfields, qualifiers, storage duration and linkage, tentative definitions, string literals, function pointers, variadics, designated initializers, compound literals, integer promotions/conversions, constant expressions, and complete control flow.

  • Specify the x86_64 data model and SysV layout in one shared target descriptor.
  • Represent types and declarations by integer IDs in flat arenas; avoid pointer-rich object graphs.
  • Reject VLAs initially if the selected kernel config forbids them; parse them well enough to diagnose precisely.
Active · freestanding C regression programs cover layout, calls, globals, pointers, aggregates, and control flow on host and stage3.
M4
GNU C kernel dialect

Implement what the corpus proves Linux uses

Add GNU statement expressions, typeof/__auto_type, attributes, alternate keywords, case ranges, zero-length arrays, anonymous aggregates, omitted conditional operands, label addresses/computed goto where observed, and the builtin families selected by the census.

  • Treat attributes by semantics: layout, section, calling convention, optimization promise, diagnostic-only, or safely ignored.
  • Lower kernel builtins to canonical operations, constants, or explicit calls—never recognize spellings in a machine emitter.
  • Preserve early, structured diagnostics for extensions not yet implemented.
Every preprocessed C file in the pinned tinyconfig parses and type-checks, even if some code-generation operations remain unsupported.
M5
Kernel objects

Promote hosted ET_REL into Kbuild-compatible objects

Extend M0's minimal system-linkable object mode while keeping it separate from Renvo's existing kernel-module wrapper. Emit arbitrary named text/data/rodata/BSS sections, symbol bindings and visibility, alignment, weak/alias symbols, section groups where required, and the x86_64 relocations used by the pinned build.

  • Add -ffunction-sections/-fdata-sections-equivalent placement only when Kbuild requests it.
  • Carry section and alignment attributes through the checked core instead of reconstructing them late.
  • Generate dependency files atomically and deterministically beside each object.
Kbuild accepts and archives a Renvo-built leaf object; readelf fixtures validate sections, symbols, relocations, and ABI without using a host compiler at test time.
M6
First real units

Walk from leaf code toward the core

Compile a deliberate sequence: small lib/ routines, generated-constant probes such as bounds/offset sources, a self-contained driver leaf, then central translation units such as init/main.c. Reduce every new failure into a minimal Renvo regression.

  • Compare exported symbol tables, section sizes, aggregate layouts, and relocations with recorded fixtures.
  • Add semantic execution tests for each newly exercised operation before accepting the kernel file.
  • Track accepted translation units monotonically in the census dashboard.
At least one real upstream kernel C object links into the reference build and survives its relevant build-time checks.
M7
Asm + atomics

Cross the unavoidable architecture boundary

Let Kbuild continue to send standalone .S files to GNU as or LLVM. For inline C assembly, parse GCC constraints, clobbers, volatile semantics, and asm goto; lower common barrier/atomic/per-CPU idioms to explicit backend operations and support a measured x86 template subset for the rest.

  • Model memory and condition-code clobbers in the canonical operation stream.
  • Make asm goto edges visible to control flow and reachability.
  • Implement atomic and overflow builtins with defined ordering and width semantics.
All target C translation units selected by the pinned tinyconfig emit objects; no GCC/Clang fallback appears in the build log.
M8
Link Linux

Produce a structurally valid vmlinux

Use the upstream linker scripts and external linker to combine Renvo C objects with externally assembled architecture objects. Fix relocation range, section ordering, discarded-section, undefined-symbol, alternative-instruction, and generated-offset failures from semantics rather than patches.

  • Run modpost, symbol/version checks, and Kbuild's normal post-link stages.
  • Validate the ELF entry point, load segments, section invariants, and required symbols.
  • Keep the build reproducible with fixed metadata inputs.
The unmodified pinned tree produces vmlinux and a bootable x86 image with Renvo as target CC.
M9
Boot + harden

Turn “it links” into “it is a kernel”

Boot under QEMU with deterministic CPU, memory, command line, and initramfs. Advance from decompressor entry to early console, scheduler, memory management, init, and an explicit PASS marker. Diagnose with serial logs, QEMU tracing, GDB, and object-level differential inspection.

  • Run the boot smoke test out of the normal one-minute preflight path.
  • Add smaller native regressions for every boot-time miscompile.
  • Re-run with optimization changes only after the unoptimized semantic path is solid.
A clean, scripted build boots twice identically and reaches the checked success marker within a fixed time and memory budget.
M10
Lose the crutches

Stretch from frontend proof to tiny toolchain

Broaden configs and architectures; compile selected Kbuild host utilities through the Go-backed C library path; optionally absorb standalone assembly and final linking into Renvo. This is beyond the first boot and must not delay it.

Renvo can rebuild the pinned kernel with progressively fewer external binary tools while preserving the compiler-size gate and resource telemetry.

05 · Frontend gate

One hard size gate. Everything else stays visible.

CPU time and memory are engineering signals, not product limits for the frontend. We record them on a fixed corpus, investigate regressions and pathological outliers, and improve them when they go wild. The hard product constraint is the compiler artifact itself.

< 2,000,000 Bthe stripped, runnable frontend plus only the Linux/x86_64 backend; measured as exact file bytes, excluding offline source/assets and every other target backend
Trackedcold CPU time and wall time on a pinned corpus, reported against the main-branch baseline rather than compared with an absolute pass/fail ceiling
Trackedpeak RSS, allocations, and per-phase high-water marks, including the worst translation unit rather than only an average
1 TUarchitectural invariant: release preprocessing, syntax, and lowering arenas before compiling the next object

Exactly what the gate measures

The measured artifact is a self-contained command-line compiler that can take Go/C source through the shared frontend and emit Linux/amd64 code. It is stripped, contains the x86_64 backend, and contains no other architecture backend, bundled module cache, documentation, forms, device data, or test corpus. The threshold is decimal: 1,999,999 bytes passes; 2,000,000 bytes does not.

Telemetry policy

Keep source text once. Store tokens, types, declarations, and scopes as small integer-indexed records. Intern identifiers once per translation unit. Use mark/reset arenas for macro expansion and function bodies. Stream object sections to bounded buffers where fixups permit. Cache completed objects by source, flags, includes, target definition, and compiler version hashes.

Every milestone records cold wall time, CPU time, peak RSS, allocation count, compiler bytes, output bytes, tokens, macro expansions, declarations, and emitted relocations. Median hides disasters, so the dashboard includes p95 and the worst translation unit.

Regression rule: CPU or memory movement does not fail on a magic number. A sustained regression against main, a sudden nonlinear curve, or one wildly expensive translation unit does require a profile and either a fix or a written explanation before merge. Improve the data structure or lifetime first; do not hide the change by resetting the baseline.
06 · Validation ladder

Reduce failures; never bless accidents.

Layer 1 · Frontend corpus

Minimal positive and negative programs for every feature. Exact diagnostics and checked-in outputs. Host and stage3 runs. Preprocessor fixtures retain token spelling and source locations.

Layer 2 · ABI/object corpus

Start with the hosted hello.o: checked symbols, string section, undefined libc call, relocations, system link, and execution. Grow into checked-in layouts, section maps, and relocation fixtures. Reference compilers may generate fixtures during explicit maintenance, never act as the normal test oracle.

Layer 3 · Pinned Linux

An opt-in, cacheable check outside ordinary preflight: preprocess, parse, emit selected units, all-C build, link, and QEMU boot. Each discovered miscompile returns to Layers 1 or 2.

Proposed Linux check modes
  • ./tools/check linux-census — refresh or compare the blocker inventory for the pinned checkout.
  • ./tools/check linux 'lib/string.o' — compile one filtered upstream object during development.
  • ./tools/check linux-c — compile every target C unit, retaining external assembly and link.
  • ./tools/check linux-boot — full opt-in image build and bounded QEMU smoke test.

These would be additive modes. They must not weaken or silently skip existing preflight, the frontend's exact binary-size gate and telemetry, or the backend's existing correctness, resource, and performance gates.

07 · Risks

The dragons are identifiable.

C semantics leak through Go-shaped source

Failure: unions, bitfields, aliasing, volatile, or integer conversions silently become Go semantics. Counter: keep the adapter for exact overlap only; introduce typed canonical C operations with executable semantic tests before accepting each divergent feature.

Inline assembly dominates the tail

Failure: parsing C succeeds but core headers expand into unsupported barriers and atomics everywhere. Counter: inventory expanded asm templates early, model constraints/CFG once, lower common idioms to typed primitives, and implement only the measured x86 residue.

Macro expansion consumes the budget

Failure: copied replacement streams and source maps multiply header size. Counter: token spans, interned names, compact hide sets, include-guard cache, expansion arenas, and per-TU high-water metrics.

Kbuild feature probes get false answers

Failure: Renvo ignores a flag, returns success, and Kbuild enables code generation it cannot honor. Counter: classify every option; accept, reject, or implement it deliberately, with probe transcript tests.

Object details become a second linker

Failure: section and relocation work sprawls into premature full linking. Counter: emit only per-TU ET_REL first, reuse the existing ELF emitter, and let upstream linker scripts plus GNU/LLVM linkers own final placement.

The test target drifts

Failure: upstream churn changes the denominator and obscures progress. Counter: pin commit/config/tool hashes; upgrade only after a boot milestone or an explicit corpus-refresh PR.

08 · Immediate sequence

The kernel preprocessor corpus is green.

The M0 object path, M1 driver contract, and M2 token stream now form permanent host-and-stage3 acceptance paths; the active edge moves to the ISO C type and declaration model.

Compact token engine

Store preprocessing tokens as three-word source spans, intern macro names in a grow-only open-addressed table, and represent rescanning exclusions as packed hide-set IDs rather than per-token object graphs.

Complete · recursive expansion remains linear enough for the first kernel closure; macro-table growth no longer causes quadratic stage3 arena consumption.

GNU translation phases

Handle splicing/comments, recursive includes and include_next, guards/pragma once, object/function/named variadic macros, #/##, conditionals, #line, predefines, forced includes, and dependency output.

Complete · the checked fixture is byte-stable on both Go-hosted and stage3 compilers and token-equivalent to GCC.

First kernel translation unit

Run the semantic portion of the real Kbuild command over forced compiler/config headers and the full devicetable-offsets.c include closure, preserving pasted SIZE_/OFF_ names and every transitive dependency.

Complete · host and stage3 emit the same 289,360-byte stream; the final stage3 observation is 0.06 s wall, 80,028 KiB peak RSS, and a 1,863,602-byte compiler.

Feed it the M2 token stream directly while keeping the M0 hosted link, M1 Kbuild handshake, and M2 host/stage3 preprocessing corpus permanently green.
