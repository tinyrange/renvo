## Highlights

Renvo 0.1.1 focuses on compiler correctness, more consistent incremental
compilation, and lower compilation overhead. It also expands the standard
library, public compiler APIs, and device examples.

### Compiler correctness

- Strengthen diagnostics for invalid declarations, assignments, calls, variadic
  arguments, conversions, interface implementations, and selector operands.
- Validate map key comparability, map indices and literals, array lengths and
  literal bounds, duplicate constant cases, and collection builtin operands.
- Preserve constant width and signedness, exact integer arithmetic, lexical
  shadowing, Unicode identifiers, and source literal validation.
- Fix slice allocation and zeroing, append and conversion semantics, captured
  function bindings, collection value identity, and integer-range iteration
  bindings.
- Preserve named return assignment order, forwarded tuple conversions,
  interface identity, string comparison order, and recoverable nil panic state.
- Align incremental lowering with whole-program linking, including default
  runtime handlers, function values, reflection metadata, and errors dispatch.
- Resolve module imports before standard-library fallback, support standalone
  Go files without a module, and track module and file language versions.

### Backends and compilation performance

- Fix nested WebAssembly call arguments and reused aggregate stack slots,
  address-taken local storage, unsigned ordering on 32-bit targets, and
  aggregate result forwarding using target-specific call-word widths.
- Improve large aggregate copies, allocation zeroing, and argument copying
  across native, WebAssembly, and VM32 backends, including overlap-safe copies.
- Reduce repeated scope and symbol searches, metadata copying, token scans,
  source compression work, and temporary allocations during compilation.
- Reuse frontend scratch arenas and output buffers across backend handoffs to
  reduce peak compiler memory use.
- Export Go object roots and isolate cached link modes; document object ABI
  boundaries and retain initialization and entrypoint behavior.
- Expand semantic regression coverage and unify Tier 1 self-hosting performance
  checks across platform workflows.

### Standard library and compiler APIs

- Add explicitly opted-in reflection metadata and JSON encoding and typed
  decoding built on that metadata.
- Support typed `errors.As` matching and wrapped `errors.Is` checks.
- Expand numeric and flag-parsing libraries, byte readers, Base64 encodings,
  FNV hashes, Unicode and UTF-16 support, and rune-aware string APIs.
- Improve formatter `Stringer` support and `Sprintln` spacing, and add unsafe
  pointer and string intrinsics with operand validation.
- Add public compiler APIs, in-memory C commands, and Makefile planning.

### Devices and experimental targets

- Add Tab5 keyboard and rotated terminal support, SDMMC DMA, FAT32 storage,
  an SD terminal shell, and display simulation coverage.
- Add RollerCAN I2C support, Chain DualKey switches and USB HID keyboard
  examples, Unit PoE-P4 Ethernet/DHCP/HTTP bring-up, and a CoreS3-SE Forms demo.
- Expand board metadata, device examples, and board-specific browser flashing.
- Add PDP-11/FP11 and Unix V7 emulator work for host and Tab5, a native Gemma 3
  runtime and tokenizer, experimental Linux backends with opt-in QEMU checks,
  and in-memory Windows ARM64 kernel driver compilation.

### Distribution

- Continue shipping fully bundled Go-hosted compilers for Linux amd64,
  Windows amd64, and macOS arm64, with the complete bundled library and
  built-in cross-compilation targets.
- Default source builds now use a minimal standard-library bundle; release
  binaries continue to use the full `renvo_bundle` configuration.
- The release workflow verifies bundled libraries and backend smoke builds on
  native runners, uploads all three binaries to a draft, and publishes only
  after the complete asset set is available.
