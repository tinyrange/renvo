## Highlights

Renvo 0.1.0 is the largest release so far. It completes the project-wide Renvo
rebrand, turns the frontend and backend into practical retargetable toolchains,
adds C as a second source language, broadens native and embedded targets, and
replaces the original browser playground with a capable project-oriented IDE.

### Distribution

- Ship one fully bundled compiler for each core development platform:
  Linux amd64, Windows amd64, and macOS arm64.
- Include the complete Renvo standard library, C library, Forms packages,
  device packages, runtime packages, fonts, and other embedded assets in every
  compiler. A separate standard-library checkout is not required.
- Keep every compiler cross-targeting: each artifact supports all Tier 1
  targets and can prepare every Tier 2 RTG backend supplied with the source
  tree.
- Build the distributions as fully bundled Go-hosted compilers so dynamic
  RTG/RBE preparation remains available alongside the built-in backends.
- Build and verify all three artifacts on their native GitHub Actions runners.
- Stage releases as drafts, upload every asset, and publish only after the full
  artifact set is present.

### Compiler and language support

- Broaden ordinary Go semantics across maps, interfaces and dynamic dispatch,
  closures, function values, arrays, complex numbers, unsafe intrinsics,
  panic/recover, defer, goroutines, channels, and `select` lowering through the
  runtime ABI.
- Improve package initialization, module and replacement resolution, build
  constraints, `//go:embed`, imported methods and structs, selector precedence,
  variadic calls, named values, conversions, constants, and wide 32-bit target
  operations.
- Add a compact C11 frontend with mixed Go/C packages, cgo-shaped declarations,
  exported Go entrypoints, C89 output modes, libc headers and implementations,
  and SQLite and compiler-bootstrap smoke coverage.
- Add `renvo run`, `renvo test`, the interactive REPL, Makefile execution,
  linked-image execution, object caching, differential testing, and clearer
  structured diagnostics.
- Make compilation contexts independent and safe for concurrent callers while
  reducing frontend and backend memory use on large programs.

### Backends and targets

- Expand and harden Linux amd64, 386, arm64, and arm; Windows amd64, 386, and
  arm64; macOS arm64; WASI; and the deterministic VM32 backend.
- Add supported Linux object, LLVM Linux amd64, ESP32-C6 flash and JTAG, and
  ESP32-S3 backends.
- Add experimental FreeBSD, OpenBSD, NetBSD, Linux kernel module, Android,
  iOS, IA-64, JVM classfile, MS-DOS COM and MZ, BIOS, UEFI, RP2040/RP2350, and
  ESP32-P4 targets.
- Introduce RTG backend bundles, RBE definitions, prepared backend artifacts,
  static imports, target descriptors, system profiles, multi-stage images, and
  a formatter for RTG and RBE sources.
- Add native linked-image JIT execution on Linux, Windows, and macOS, together
  with executable, object, kernel, firmware, and browser image validation.

### Embedded systems and devices

- Add board support and examples for M5Stack AtomS3 Lite, Cardputer Adv,
  NanoC6, StickS3, and Tab5, plus Raspberry Pi Pico-family boards.
- Add ESP32 USB serial/JTAG transport, stable hot reload, WebSerial and WebUSB
  flashing, CMSIS-DAP support, serial monitoring, and serial plotting.
- Add display, touch, keyboard, GPIO, I2C, SPI, LED-strip, accelerometer,
  environmental-sensor, and scale integrations used by the board examples.
- Add Linux and xv6 boot experiments, BIOS long-mode and UEFI Linux boot flows,
  and reproducible emulator checks for promoted embedded targets.

### Standard library and Forms

- Expand `bytes`, `fmt`, `io`, `math`, `math/bits`, `os`, `path`, `sort`,
  `strconv`, `strings`, `sync`, `testing`, `unicode/utf8`, and `unsafe`
  compatibility.
- Add concurrency runtime handlers and serial scheduling support.
- Extend Forms across browser, Android, iOS, macOS, Windows, and embedded
  framebuffer targets, including accessibility plumbing and hardware-accelerated
  drawing paths.
- Add bundled Go fonts and richer graphics, terminal, input, and layout support.

### Browser IDE

- Replace the legacy playground with a responsive project workbench containing
  an explorer, Monaco editor, terminal, previews, diagnostics, build controls,
  target selection, and persistent workspaces.
- Add quick-open navigation across commands, workspace files, samples, standard
  packages, and target definitions.
- Add a virtual shell with the Renvo CLI, filesystem commands, history, line
  editing, completion, persistent build outputs, and WASI execution.
- Add Go, C, RTG, RBE, and Makefile language assistance; parser-owned import and
  selector completion; device flashing; serial output; and binary inspection.
- Add browser-side build profiling, asset retry and caching, offline service
  worker support, mobile layouts, and broad JavaScript smoke coverage.

### Quality and project structure

- Establish explicit backend support tiers and required cross-platform CI for
  Linux, Windows, macOS, WASI, VM32, and promoted ESP targets.
- Add strict compiler performance, binary-size, memory, and VM execution gates.
- Consolidate generated sources, target metadata, backend definitions, corpus
  expectations, and the repository-owned `tools/check` presubmit driver.
- Greatly expand frontend, backend, standard-library, device, browser, and
  differential regression coverage.
