Renvo Machine Definitions and Dynamic Backends Plan

Implementation plan for #129, the machine-definition backend rewrite, followed by #131, on-the-fly targets with staged native backend specialization.

Outcome

A Renvo compiler will be able to compile deterministic .rtg machine definitions into ordinary, direct Go backend code. Generated backends will implement the full backend contract without interpreting recipes while compiling user programs. Once that generated path is proven, an existing Renvo compiler will be able to accept a previously unknown target definition, prepare a host-native specialized backend using Renvo itself, cache it, and use it in the same invocation.

The work is one initiative with a strict dependency: #129 establishes the definition language and generated backend contract, proves them on AArch64 and amd64, then migrates every advertised backend; #131 adds dynamic frontend discovery, preparation, execution, artifacts, and caching. The two issues should not be implemented as one large branch.

Definition of Done

Issue #129

  • A documented, versioned .rtg language describes IR operations, architectures, ABIs, runtimes, image formats, relocations, and target composition.
  • The parser, resolver, validator, canonicalizer, and Go emitter expose byte-slice-based APIs and compile with Renvo.
  • Generated source is deterministic, self-hostable, and records a sorted unit/hash manifest, generator version, and either the selected canonical target or an explicit universal marker.
  • Generated production backends contain direct Go control flow and calls, with no recipe interpreter, definition AST, dynamic property lookup, or generic target dispatch in the user-program code-generation path.
  • Every advertised backend is migrated to the generated contract, including AArch64, ARM, 386, amd64, Wasm, and VM targets.
  • Each migrated architecture keeps genuinely algorithmic work as ordinary embedded Go in its owning definition; no advertised target remains on a parallel legacy backend.
  • Target-independent semantic lowering is shared and no architecture backend recursively lowers frontend expressions.
  • Fixed-target compilation prunes unrelated generated architectures, ABIs, runtimes, and formats.
  • Migration comparisons demonstrate byte equivalence with the replaced legacy outputs where deterministic and semantic equivalence everywhere else.
  • The complete backend suite, frontend suite, and full self-hosting suite pass without loosening any correctness, time, memory, or binary-size gate.

Issue #131

  • renvo -backend machines.rtg -t target/name accepts a target unknown to the release compiler; -t remains authoritative when a file declares several targets.
  • The frontend obtains target-dependent source-selection and layout facts before collecting or checking source.
  • The generated target-specialized backend is compiled for the current host by Renvo without invoking the host Go toolchain.
  • The frontend invokes that backend through a stable, versioned protocol and produces the requested output in one command on process-capable hosts.
  • Prepared backends are cached by content and compiler compatibility, and reusable .rtgb artifacts can be distributed without source definitions.
  • RTGU units are bound to the definition and descriptor used by the frontend; mismatched units are rejected before machine-code generation.
  • Embedders can replace persistent storage and backend execution without changing the definition compiler.
  • Cold preparation, warm end-to-end compilation, backend-core execution, memory, and artifact size are measured separately and gated once stable baselines exist.

Non-Negotiable Design Rules

  • Definitions compile ahead of time. No generic recipe VM or definition interpreter may remain in the generated backend hot path.
  • Direct emission remains the initial model. Do not add an instruction tape, decode pass, instruction objects, or runtime function registry merely to support generation.
  • Generated code stays in Renvo's backend subset. Use simple structs, slices, strings, integers, booleans, loops, conditionals, and direct calls. Avoid maps, interfaces, reflection, generics, closures, and function values.
  • No hidden backend. A definition owns its ISA encoding, address forms, selection rules, ABI adapters, runtime boundary, relocations, image layout, and composition. A small generated-runtime library may provide target-neutral byte, label, relocation, section, hashing, and signing primitives, but not an x86 encoder or OS backend.
  • Definitions are closed units. A distributable machine definition is one self-contained file. It may contain many reusable named declarations and target compositions, but it cannot depend on imported .rtg files or an ambient definition search path.
  • Use Go for algorithms. A definition may contain embedded Go declarations written in Renvo's supported subset. Prefer declarative tables for facts and composition; use Go for encoding, selection, ABI shuffles, runtime adapters, and image algorithms where Go is simpler. Embedded Go is parsed and type-checked, then emitted as ordinary declarations in the generated backend package. It is part of the file and definition hash—not an external hook.
  • Composition resolves during generation. Architecture, ABI, runtime, relocation, output format, pointer width, and endianness choices become constants and direct calls in generated source.
  • Target selection is explicit. A source definition supplies target choices but never chooses one from its filename, declaration order, or contents. Existing option resolution selects the canonical target, with an explicit -t authoritative over system defaults. A prepared artifact is already fixed to exactly one target.
  • One production authority. Generated and legacy implementations may coexist behind test-only comparison during migration, but production compilation must select exactly one implementation.
  • Existing gates remain authoritative. Do not modify backend/main_test.go or loosen target-specific performance limits to make the rewrite pass.
  • No host Go dependency at use time. Host Go may build the initial development tool while bootstrapping, but the shared parser, validator, and emitter must converge immediately toward Renvo-compatible source.

One Coherent .rtg Language

Renvo already uses .rtg files for hosted system profiles. The machine-definition work must extend that language rather than create a second incompatible parser for the same extension. A document is a deterministic sequence of named top-level declarations:

  • system: an existing target plus binary and arena constraints;
  • unit: the required stable namespace of a machine-definition file;
  • ir: the canonical direct-emitter operation contract;
  • arch: registers, locations, instruction facts, operation bindings, and references to local Go implementations;
  • abi: call words, stack rules, clobbers, aggregate results, entry conventions, and external-call marshalling;
  • runtime: startup and the supported runtime-operation surface;
  • format: image sections, headers, relocations, symbols, and format constants;
  • target: composition of one architecture, ABI, runtime, and format with target-specific parameters.
  • go backend: parsed package-level Go declarations implementing algorithms named by the declarations above.

Existing system profiles remain valid. New declaration kinds use the same lexer, source positions, literals, comments, numeric units, diagnostics, canonicalization, and version rules.

A machine-definition document is a closed package. It can define an ISA once and combine it with several ABIs, hosted runtimes, firmware environments, and image formats in the same file. This follows the separation in issue #24 without forcing one file per OS/architecture tuple: Linux, Windows, UEFI, Darwin, and future BSD x86-64 targets reuse named components inside the file. The only external contract is a versioned built-in IR vocabulary such as direct_emitter_v1.

A machine-definition file declares exactly one stable unit name. Canonical target names are exported for -t; all other RTG declarations and embedded Go names are local to the unit. During emission the generator rewrites declared Go identifiers and their resolved references with a deterministic unit prefix. Authored Go stays readable, fixed and universal builds use identical symbols, and combining several closed files cannot create package-level name collisions.

A go backend { ... } block contains ordinary package-level Go declarations. The outer .rtg parser finds the balanced block; its body is handed intact to the existing Go parser and checker, restricted to the self-hostable backend subset, and emitted as declarations in the specialized backend package. This is source-to-source generation: calls to a named embedded function become ordinary direct Go calls. The definition compiler supplies a small typed API for byte emission, labels, relocations, sections, diagnostics, and bound IR locations. The block has no package clause or imports and cannot reach host services during generation. The leading definition 1 selects both the declarative grammar and this RTG Go API; an incompatible API change requires a new definition-language version.

Parsing and diagnostics

  • The core accepts source bytes and a logical filename and returns definitions plus structured diagnostics; filesystem traversal stays in a thin host wrapper.
  • Every token and declaration retains byte offsets for precise diagnostics without retaining unnecessary source copies.
  • Unknown fields, duplicate declarations, duplicate unit names, canonical target or alias collisions, invalid literals, reference cycles, and version mismatches fail explicitly.
  • The parser does not evaluate Go, accept raw generated-source fragments, or splice unchecked identifiers into output.
  • Embedded Go compiler directives, line directives, package clauses, and imports are rejected, so comments and source paths cannot change generated semantics.
  • The RTG identifier prefix is reserved for the versioned generated-backend API; embedded declarations cannot shadow it.
  • Malformed-input tests cover truncation at every token boundary, invalid UTF-8 where relevant, deep nesting limits, oversized tables, duplicate names, and cyclic composition.

Canonicalization and identity

  • Canonical form is independent of comments, whitespace, input path, and declaration ordering where order has no semantics.
  • Names and literal values are normalized before hashing.
  • Embedded Go is parsed first and contributes its normalized syntax tree to the definition hash; formatting and comments do not change identity, while any executable change does.
  • The whole closed definition file contributes to the canonical hash; machine definitions have no imported .rtg dependencies.
  • The definition hash identifies the complete file's semantics, while the canonical target name identifies the selected composition within that file.
  • Initially, changing any declaration conservatively invalidates prepared artifacts for every target in the file. A reachable per-target semantic hash is deferred until real cache behavior justifies its extra complexity.
  • The generator version, backend-kernel version, RTGU schema version, and host tuple remain separate compatibility fields rather than being hidden inside the definition hash.

Core APIs and Ownership

Package names may change during implementation, but ownership should remain separated along these boundaries:

Layer Responsibility Must not own
Definition core Lexing, parsing, resolving, validation, canonicalization, hashing, and structured diagnostics. Filesystem policy, process execution, cache paths, or user-program compilation.
IR contract Stable operation names, typed operands, locations, effects, clobbers, control flow, labels, symbols, and relocation effects. Source-language expression trees or target-specific instruction selection.
Go generator Deterministic Renvo-subset source, direct dispatch, specialized constants and wrappers, plus validated embedded Go declarations. A runtime definition representation or host-Go-only formatting dependency.
Backend kernel Shared semantic lowering plus target-neutral byte, label, relocation, section, hashing, signing, and image-buffer primitives. Target-name fan-out that generation can resolve.
Frontend descriptor Source selection, scalar and pointer widths, alignment, endianness, runtime/output capabilities, aliases, and definition identity. Registers, encodings, relocations, or image-construction details.
Preparation service Generate specialized source, invoke the explicit host-bootstrap backend, package artifacts, and report preparation diagnostics. Normal frontend checking or recursive backend preparation.
Cache and runner Artifact persistence and execution on process-capable hosts or through embedding callbacks. Definition semantics or generated code selection.

Conceptual in-memory operations: 

ParseDefinitions(source []byte, filename string) ParseResult
ResolveDefinitions(parsed ParseResult) ResolveResult

Result values should carry output bytes, structured diagnostics, descriptor data, and success state directly. They should not require interfaces or callbacks in the self-hosted core. Dynamic preparation always uses the fixed-target entrypoint. The universal entrypoint combines several closed definition units for the bundled all-target compiler and equivalence tests, rejects duplicate canonical targets, and generates explicit target dispatch; each fixed output contains none.

Frontend Target Descriptor

The descriptor is the only definition projection visible to frontend source collection and semantic checking. Its initial information must include:

  • canonical target name and aliases;
  • OS/architecture and explicit build tags;
  • int, data pointer, code pointer, and function pointer widths;
  • maximum alignment and byte order;
  • runtime capabilities and output capabilities;
  • definition hash and descriptor schema version;
  • default arena policy or other frontend-visible hosted constraints only where they affect program construction.

Registers, instruction alternatives, ABI lowering, relocations, imports, and image-format details never enter the frontend descriptor. Built-in targets and external definitions use the same descriptor path so behavior cannot diverge.

IR and Generated Backend Contract

IR schema

Start from backend/docs/backend-ir.md and the existing direct emitter boundary. Each operation declaration records:

  • a stable operation name and typed operands;
  • primary, secondary, tertiary, stack, frame, call-word, label, symbol, data, and BSS location reads and writes;
  • clobbers and preserved locations;
  • memory width, signedness, and alignment behavior;
  • control-flow, fallthrough, branch, call, and return behavior;
  • label, symbol, relocation, and fixup effects;
  • required target capabilities and any explicitly permitted rejection.

The schema generates completeness checks, neutral wrappers where useful, effect contracts, documentation projections, and boundary tests. Semantic lowering remains handwritten once in the shared backend kernel.

Architecture generation

  • Instruction tables declare names, fixed opcode facts, widths, and the local embedded Go function that emits them.
  • Instruction rows are validated for required fields, literal widths, referenced embedded-Go signatures, and compatibility with the bound IR operation.
  • The generator specializes table rows into direct Go wrappers; the actual encoding algorithm remains readable ordinary Go in the same definition.
  • Width and signedness variants are specialized when that removes runtime branches without materially inflating specialized binaries.
  • Fixed byte sequences use the widest existing append operation that preserves output and code size.
  • Generated names come only from the stable unit name and resolved local identifiers through one deterministic mangling rule.

ABI, runtime, and format generation

  • ABI definitions supply register/location mappings, stack alignment, saved and clobbered registers, overflow arguments, aggregate results, entry arguments, and foreign-call rules.
  • Runtime definitions map the small Renvo runtime-operation surface to declared syscalls, imports, host facilities, firmware entry points, or precise unsupported diagnostics.
  • Format definitions supply header constants, sections, alignments, machine identifiers, relocation mappings, and direct append/patch layout code.
  • Nontrivial target-format algorithms are embedded Go; only genuinely target-neutral buffer, hashing, and signing primitives are shared.
  • Target composition validates compatible word width, pointer width, endianness, ABI, runtime capabilities, relocations, and image format before source is emitted.

Embedded Go boundary

Algorithms live in explicit go backend blocks in the same definition that names them. They are not string fragments: the existing Go parser produces an AST, the definition checker resolves their RTG API and generated-symbol references, and the Go emitter writes those declarations into the specialized backend package. The only library boundary is a closed, target-neutral API for bytes, labels, relocations, sections, diagnostics, and image buffers. Every target-specific constant and choice remains in the file.

Implementation Phases

Phase 0: Freeze baselines

  1. Record deterministic output hashes for representative programs on every advertised target.
  2. Record semantic omnibus results where images contain nondeterministic or platform-specific metadata.
  3. Record current specialized and universal compiler size, runtime, peak RSS, writable reservation, and self-host measurements.
  4. List the current IR operation surface and every architecture, ABI, runtime, format, relocation, and target-selection branch.
  5. Add comparison helpers only where they expose production output without changing the compiler or harness behavior.

Exit condition: the migration can identify a changed byte, semantic result, resource measurement, or pruning result before any generated backend becomes authoritative.

Phase 1: Shared language and generator core

  1. Implement the Renvo-compatible lexer, parser, source positions, diagnostics, resolver, canonicalizer, and hash calculation.
  2. Move the existing hosted system profile grammar onto the shared parser without changing accepted files or option behavior.
  3. Define versioned top-level declaration and reference rules.
  4. Implement deterministic source emission without depending on go/format.
  5. Add a small but real AArch64 encoding slice that generates compilable direct Go.
  6. Compile the generator and its generated source through both host Go and Renvo.
  7. Add a stale-output check and generated-file header carrying a sorted unit/hash manifest, generator version, and either the selected canonical target or an explicit universal marker.

Exit condition: one definition can be parsed and validated in memory, generate byte-identical Go twice, compile through Renvo, and emit verified AArch64 instruction bytes. Production backends are unchanged.

Phase 2: Complete AArch64 vertical slice

  1. Describe every AArch64 primitive needed by the direct-emitter IR.
  2. Express immediate synthesis, address materialization, and branch patching as embedded Go beside declarative opcode and relocation facts.
  3. Define shared AArch64 locations plus the AAPCS64, Darwin, and Windows ARM64 ABI differences.
  4. Define Linux, Darwin, and Win32 runtime composition and ELF64, Mach-O 64, and PE64 format parameters.
  5. Generate test-only AArch64 handlers beside the legacy implementation.
  6. Compare instruction streams, relocations, section layouts, executable images, runtime behavior, linkstatic calls, GUI subsystem output, and self-host results.
  7. Measure generated specialized compiler size, runtime, RSS, and pruning before switching production dispatch.

Exit condition: generated Linux, Darwin, and Windows ARM64 paths satisfy all current tests and gates and differ from legacy output only where explicitly reviewed and semantically equivalent.

Phase 3: Make generated AArch64 authoritative

  1. Switch the production AArch64 path to generated handlers.
  2. Remove superseded AArch64 encoding and target fan-out after the comparison suite is green.
  3. Keep only target-neutral shared algorithms and document their complete declared inputs and effects.
  4. Verify fixed-target pruning removes unrelated ABI, runtime, and format compositions.
  5. Run all backend targets, the complete frontend suite, and full self-hosting.

Phase 4: Neutral lowering and a non-AArch64 proof

  1. Move remaining target-independent semantic lowering out of architecture-prefixed code.
  2. Migrate amd64 next because it exercises variable-length instructions, immediate alternatives, ModRM/SIB addressing, branch relaxation, and multiple hosted formats.
  3. Define ModRM/SIB and relaxation once as ordinary embedded Go; do not invent a macro language or hide x86 in an external backend.
  4. Run byte and semantic equivalence across Linux and Windows amd64, linkstatic behavior, PIE paths, stack behavior, and self-hosting.
  5. Switch amd64 production dispatch only after resource gates and fixed-target size remain within their existing limits.

Exit condition: one fixed-width RISC and one variable-width CISC backend use the generated system in production, proving the model is not architecture-specific.

Phase 5: Complete the built-in backend migration

  1. Migrate 386 with its own closed definition while reusing the IR contract and target-neutral semantic lowering.
  2. Migrate ARM while preserving its target-specific instruction and relocation constraints.
  3. Migrate Wasm after the native IR contract is stable; keep structured-control and module construction algorithmic.
  4. Migrate VM targets using the same canonical operation and composition contracts without pretending they are native ISAs.
  5. Generate the target registry, completeness projections, documentation, and stale checks from definitions.
  6. Remove the final obsolete dispatch fan-out and duplicated legacy emitters.

Exit condition: every advertised target is generated from its owning closed definition, and #129's full correctness, self-hosting, pruning, size, memory, and runtime criteria pass.

Phase 6: Descriptor-first frontend and RTGU binding

  1. Make built-in and external target selection produce the same versioned descriptor.
  2. Change option handling so syntax is parsed before target resolution, but target-dependent validation occurs after descriptor resolution.
  3. Resolve the descriptor before filename suffix filtering, build-tag selection, type sizing, alignment, checking, or lowering.
  4. Stop reconstructing build tags and target facts from target-name prefixes and suffixes.
  5. Add canonical target identity, definition hash, and descriptor version to the canonical RTGU binding.
  6. Make every backend reject units bound to an incompatible definition before code generation.
  7. Preserve existing -t and -system precedence through the descriptor path; a definition supplies choices and may never overwrite an explicitly selected target.

Phase 7: Host-native backend preparation

  1. Add an explicit preparation pipeline: parse, validate, canonicalize, project descriptor, generate source, compile for the host, and package.
  2. Compile generated source through a dedicated built-in host-bootstrap backend path that cannot recursively request another prepared backend.
  3. Use existing frontend host integration to run prepared programs; do not add a generic backend syscall solely for process execution.
  4. Define a one-shot versioned protocol using canonical RTGU input, target output, structured diagnostics, and explicit failure status.
  5. Support process-free embedders by separating preparation from execution and allowing an application-supplied runner.
  6. Keep all intermediate source and artifacts in memory when the embedding environment supplies suitable services.

Phase 8: Cache, artifacts, and one-command workflow

  1. Define a content-addressed cache key from canonical definition hash, selected canonical target, generator version, backend-kernel version, RTGU schema, host tuple, and optimization mode.
  2. Write cache entries atomically, validate metadata before reuse, and ignore corrupt or incompatible entries.
  3. Define a versioned, single-target .rtgb container containing the public descriptor, compatibility metadata, definition identity, canonical target, host tuple, and native payload.
  4. Add explicit renvo backend build machines.rtg -t target/name -o target.rtgb preparation.
  5. Add implicit preparation and cache reuse through renvo -backend machines.rtg -t target/name.
  6. Accept prepared .rtgb artifacts through the same option and validate them before frontend source collection; a supplied -t must match the artifact's fixed target.
  7. Demonstrate a previously unknown target from definition to output without invoking host Go.

Phase 9: Release topology and cleanup

  1. Build a release compiler containing the frontend, definition compiler, backend kernel, and only the bootstrap backend required for its host.
  2. Supply at least one former built-in output target exclusively as a dynamically prepared backend.
  3. Verify cold preparation and warm cache-hit behavior on Linux, Darwin, and Windows process-capable hosts.
  4. Document the two-step workflow for environments such as WASI that cannot directly spawn native prepared backends.
  5. Add a persistent worker protocol only if measured process startup or RTGU transfer materially violates the warm gate.
  6. Remove compatibility code that no longer protects a supported migration or artifact version.

Prepared Backend Protocol

The first protocol should be deliberately small and one-shot:

  • the prepared artifact exposes protocol, descriptor, definition, canonical target, kernel, RTGU, and host compatibility metadata;
  • the caller supplies one canonical, target-bound RTGU unit and backend options;
  • the backend returns one output image or structured diagnostic result;
  • transport maps cleanly to stdin/stdout/stderr and exit status for a process runner but is also representable as in-memory byte slices;
  • protocol version negotiation fails before the unit is decoded;
  • no cache paths, generated source paths, or host-specific filesystem assumptions appear in the core protocol.

A framed persistent worker may reuse the same request and result payloads later. It is not part of the first implementation unless measurements show that process startup prevents the required warm performance.

Prepared Artifact and Cache Rules

A machine definition is source code and has the same trust boundary as a Go dependency. Parsing, validation, canonicalization, and descriptor reading never execute its embedded Go. Preparation compiles that Go, and the resulting backend executes only when the user explicitly selects the definition or a prepared artifact derived from it.

  • .rtgb uses an explicit magic, version, bounded section lengths, and deterministic metadata encoding.
  • The public descriptor is readable before loading or executing the native payload.
  • A single-host payload is sufficient initially; multi-host packaging is an extension, not a prerequisite.
  • Cache keys never depend on source paths, timestamps, comments, or whitespace.
  • Cache lookup validates all compatibility fields and payload integrity.
  • Preparation failures are not cached as successful artifacts.
  • Concurrent preparation of the same key must not expose partial files or corrupt entries.
  • Embedded declarations can only enter generated source through the parsed Go AST; package clauses, imports, unsafe facilities, unsupported language features, unresolved names, and undeclared RTG API access are rejected before emission.

Testing and Validation

Definition-language tests

  • Golden parsing and canonicalization for every declaration kind.
  • Embedded-Go tests for balanced-block extraction, existing-parser diagnostics, forbidden package/import/feature rejection, name resolution, normalized hashing, and deterministic AST emission.
  • Unit-namespace tests proving fixed and universal emission apply identical mangling and reject duplicate units, canonical targets, generated names, and reserved RTG declarations.
  • Deterministic generation across repeated runs and harmless source reordering.
  • Malformed definitions for missing operations, invalid literal widths, mismatched Go signatures, undeclared clobbers, cycles, unresolved algorithm references, relocation gaps, and incompatible composition.
  • Boundary tests for registers, signed and unsigned immediates, displacements, branches, alignment, relocation addends, and fallback selection.
  • Generated source compilation through both host Go and Renvo.
  • Stale checked-in output detection through the ordinary generation workflow.

Backend equivalence tests

  • Instruction-byte comparison at the primitive encoder boundary.
  • Whole text/data/BSS, relocation, symbol, import, and image comparison where deterministic.
  • Semantic execution comparison through the backend omnibus and target end-to-end suites.
  • Fixed-target reachability and binary inspection proving unrelated target implementations are absent.
  • Stage1, stage2, and stage3 self-hosting for each migrated host target.
  • Cross-target compilation through the bundled frontend.

Dynamic workflow tests

  • Unknown definition descriptor resolution before source selection.
  • Multi-target definitions require and honor the selected canonical target; source definitions never override -t, and mismatched fixed-target artifacts are rejected.
  • Build-tag and filename selection driven by descriptor data rather than target spelling.
  • Cold preparation followed by a cache hit with byte-identical artifact identity.
  • Corrupt, truncated, stale, wrong-host, wrong-schema, and wrong-definition .rtgb rejection.
  • RTGU definition mismatch rejection before backend work begins.
  • Concurrent preparation and cache publication.
  • Process runner and in-memory embedding runner parity.
  • Closed-definition workflow using a prepared artifact without retained generated source.

Required suite discipline

  • Run targeted package tests while a phase is under development.
  • Run the complete ./backend harness with its unchanged resource gates before every production backend switch.
  • Run the complete ./frontend_tests suite, including full bundled all-target and self-hosting coverage.
  • Run explicit package sets rather than go test ./..., which descends into independent corpus modules.
  • Use systemd-run --user memory limits for expensive self-host and concurrency validation so a regression cannot exhaust the development host.
  • Do not modify backend/main_test.go or performance-test constraints as part of this work.

Performance Plan

Existing backend runtime, RSS, and specialized binary-size limits remain hard constraints throughout migration. Dynamic preparation introduces additional measurements that must not be conflated:

Measurement Includes Purpose
Backend core Prepared specialized backend processing one RTGU unit. Detect generated-code or backend-kernel regressions.
Cold preparation Parse, validate, generate, self-compile, and package. Bound first-use cost independently of normal compilation.
Warm end to end Frontend, cache lookup, process startup or runner call, RTGU transfer, backend, and output transfer. Represent normal user-visible cached compilation.
Artifact size Specialized backend executable and prepared container overhead. Prove specialization removes unrelated targets.
Memory Peak frontend, preparation, and prepared-backend RSS measured separately and together. Prevent staging from hiding a larger total footprint.
  • Collect distributions before introducing new numeric gates; do not weaken existing gates during that collection.
  • Prefer direct generated conditionals and calls over data-driven dispatch in hot code.
  • Measure code-size effects before generating many width or immediate variants.
  • Use persistent workers only in response to measured startup cost.
  • After migration stabilizes, tighten gates only when CI distributions show safe cross-platform margin.

Pull Request Strategy

Each pull request should leave the production compiler fully usable and all required checks green. A practical sequence is:

  1. Baselines and comparison helpers.
  2. Shared .rtg parser, canonicalization, and deterministic emitter with an AArch64 encoding proof.
  3. Complete test-only generated AArch64 backend.
  4. Production AArch64 switch and legacy cleanup.
  5. Neutral semantic lowering and generated amd64 proof.
  6. Production amd64 switch.
  7. 386, ARM, Wasm, and VM migrations in focused target PRs.
  8. Generated registry, documentation, and final legacy dispatch removal.
  9. Descriptor-first frontend and RTGU definition binding.
  10. Host-bootstrap preparation and one-shot backend protocol.
  11. Content-addressed cache and .rtgb artifact.
  12. One-command external target flow and release-topology conversion.

A PR may be split further when reviewability or CI runtime demands it, but it should not land a second parser, an unused general framework, a disabled production path with no equivalence test, or a partially authoritative backend.

Risks and Controls

The definition language grows into a general compiler framework. Add declarative constructs only for recurring facts and composition; write algorithms as parsed Go against the small target-neutral RTG API.
Two incompatible meanings of .rtg. Use one lexer, parser, diagnostic model, canonicalization scheme, and version policy for system and machine declarations.
Generated source is larger or slower than handwritten emitters. Measure every production switch, choose inline versus helper generation deliberately, and preserve fixed-target pruning.
Legacy and generated implementations silently diverge. Run byte-level and semantic dual-path comparisons before each switch, then remove the unused production path.
Host-bootstrap compilation recursively prepares itself. Use an explicit bootstrap entrypoint bound to the built-in host backend, not normal target resolution.

Deferred Work

  • An encyclopedic catalog of ISA instructions that no supported backend operation uses.
  • A general-purpose TableGen-like language.
  • Runtime plugins or dynamically loaded backend libraries.
  • A persistent worker before measurements justify it.
  • Multi-host payloads inside one .rtgb artifact.
  • Remote or shared-network backend caches.
  • Reachability-based per-target semantic hashes; the initial whole-file hash intentionally favors simple, safe invalidation.
  • Embedded-board composition beyond the existing separate freestanding and board contracts.
  • New source-language features unrelated to descriptor correctness.

Worked x86-64 .rtg Definition

Backend authors write one closed file. This example defines the x86-64 encoder, architecture, internal and external ABIs, Linux and Windows runtimes, ELF/PE/relocatable formats, and three complete target compositions. Named declarations preserve the ISA/ABI/runtime/format separation required by issue #24 without imports or one file per target tuple. Additional x86-64 environments extend this same authority file.

The declarative layer has tables, named bindings, and bounded layout expressions for constants, offsets, alignment, conditionals, and repeated fields. It has no user-defined loops, macros, inheritance, or general programming facilities. Algorithms are written once in embedded Go using the parser Renvo already has. The generator emits that code as normal declarations and specializes table rows into direct calls. Only target-neutral byte, label, relocation, section, diagnostic, and image-buffer primitives are supplied; x86 encoding and OS behavior remain visible in this file.

Authored definition

definition 1
unit x86_64
implements direct_emitter_v1

# X86 algorithms are ordinary Go emitted into the generated backend package.
go backend {
    func x86Low3(reg RTGRegister) byte {
        return byte(reg.Code & 7)
    }

    func x86High(reg RTGRegister) byte {
        return byte(reg.Code>>3) & 1
    }

    func x86Opcode(out *RTGEmitter, opcode uint32) {
        if opcode > 0xff {
            out.Byte(byte(opcode >> 8))
        }
        out.Byte(byte(opcode))
    }

    func x86REX(
        out *RTGEmitter,
        wide bool,
        reg RTGRegister,
        index RTGRegister,
        base RTGRegister,
        byteRegister RTGRegister,
    ) {
        w := byte(0)
        if wide {
            w = 1
        }
        r := x86High(reg)
        x := byte(0)
        if index.Valid {
            x = x86High(index)
        }
        b := byte(0)
        if base.Valid {
            b = x86High(base)
        }
        needsByteREX := byteRegister.Valid && byteRegister.Code >= 4
        if w != 0 || r != 0 || x != 0 || b != 0 || needsByteREX {
            out.Byte(0x40 | w<<3 | r<<2 | x<<1 | b)
        }
    }

    func x86ModRM(out *RTGEmitter, mode byte, reg byte, rm byte) {
        out.Byte(mode<<6 | (reg&7)<<3 | rm&7)
    }

    func x86Memory(out *RTGEmitter, reg byte, address RTGAddress) {
        if address.Target.Valid {
            x86ModRM(out, 0, reg, 5)
            out.Rel32Addend(address.Target, address.Addend)
            return
        }

        base := address.Base
        index := address.Index
        displacement := address.Displacement
        needsSIB := index.Valid || x86Low3(base) == 4
        mode := byte(0)
        if displacement != 0 || x86Low3(base) == 5 {
            mode = 2
            if RTGSignedFits(displacement, 8) {
                mode = 1
            }
        }

        if needsSIB {
            x86ModRM(out, mode, reg, 4)
            indexCode := byte(4)
            if index.Valid {
                indexCode = x86Low3(index)
            }
            out.Byte(byte(RTGLog2(address.Scale))<<6 |
                indexCode<<3 | x86Low3(base))
        } else {
            x86ModRM(out, mode, reg, x86Low3(base))
        }

        if mode == 1 {
            out.Byte(byte(displacement))
        } else if mode == 2 {
            out.Uint32(uint32(displacement))
        }
    }

    func x86RRRM(
        out *RTGEmitter,
        opcode uint32,
        destination RTGRegister,
        source RTGRegister,
        width int,
    ) {
        if width == 16 {
            out.Byte(0x66)
        }
        byteRegister := RTGNoRegister
        if width == 8 {
            byteRegister = source
        }
        x86REX(out, width == 64, source, RTGNoRegister, destination, byteRegister)
        x86Opcode(out, opcode)
        x86ModRM(out, 3, x86Low3(source), x86Low3(destination))
    }

    func x86RR(
        out *RTGEmitter,
        opcode uint32,
        destination RTGRegister,
        source RTGRegister,
        width int,
    ) {
        x86REX(out, width == 64, destination, RTGNoRegister, source, RTGNoRegister)
        x86Opcode(out, opcode)
        x86ModRM(out, 3, x86Low3(destination), x86Low3(source))
    }

    func x86RMR(
        out *RTGEmitter,
        opcode uint32,
        destination RTGRegister,
        address RTGAddress,
        width int,
    ) {
        if width == 16 {
            out.Byte(0x66)
        }
        x86REX(out, width == 64, destination, address.Index, address.Base, RTGNoRegister)
        x86Opcode(out, opcode)
        x86Memory(out, x86Low3(destination), address)
    }

    func x86RRM(
        out *RTGEmitter,
        opcode uint32,
        address RTGAddress,
        source RTGRegister,
        width int,
    ) {
        if width == 16 {
            out.Byte(0x66)
        }
        byteRegister := RTGNoRegister
        if width == 8 {
            byteRegister = source
        }
        x86REX(out, width == 64, source, address.Index, address.Base, byteRegister)
        x86Opcode(out, opcode)
        x86Memory(out, x86Low3(source), address)
    }

    func x86Group(
        out *RTGEmitter,
        opcode uint32,
        selector byte,
        operand RTGRegister,
        width int,
    ) {
        x86REX(out, width == 64, RTGNoRegister, RTGNoRegister, operand, RTGNoRegister)
        x86Opcode(out, opcode)
        x86ModRM(out, 3, selector, x86Low3(operand))
    }

    func x86GroupImmediate(
        out *RTGEmitter,
        opcode uint32,
        selector byte,
        operand RTGRegister,
        value int64,
        width int,
    ) {
        x86REX(out, width == 64, RTGNoRegister, RTGNoRegister, operand, RTGNoRegister)
        if RTGSignedFits(value, 8) {
            out.Byte(0x83)
            x86ModRM(out, 3, selector, x86Low3(operand))
            out.Byte(byte(value))
            return
        }
        x86Opcode(out, opcode)
        x86ModRM(out, 3, selector, x86Low3(operand))
        out.Uint32(uint32(value))
    }

    func x86GroupImmediate8(
        out *RTGEmitter,
        opcode uint32,
        selector byte,
        operand RTGRegister,
        value byte,
        width int,
    ) {
        x86Group(out, opcode, selector, operand, width)
        out.Byte(value)
    }

    func x86GroupMemoryImmediate(
        out *RTGEmitter,
        opcode uint32,
        selector byte,
        address RTGAddress,
        value int64,
        width int,
    ) {
        x86REX(out, width == 64, RTGNoRegister, address.Index, address.Base, RTGNoRegister)
        if RTGSignedFits(value, 8) {
            out.Byte(0x83)
        } else {
            x86Opcode(out, opcode)
        }
        x86Memory(out, selector, address)
        if RTGSignedFits(value, 8) {
            out.Byte(byte(value))
        } else {
            out.Uint32(uint32(value))
        }
    }

    func x86MultiplyImmediate(
        out *RTGEmitter,
        opcode uint32,
        destination RTGRegister,
        source RTGRegister,
        value int64,
        width int,
    ) {
        x86REX(out, width == 64, destination, RTGNoRegister, source, RTGNoRegister)
        if RTGSignedFits(value, 8) {
            out.Byte(0x6b)
        } else {
            x86Opcode(out, opcode)
        }
        x86ModRM(out, 3, x86Low3(destination), x86Low3(source))
        if RTGSignedFits(value, 8) {
            out.Byte(byte(value))
        } else {
            out.Uint32(uint32(value))
        }
    }

    func x86OpcodeRegister(out *RTGEmitter, opcode byte, operand RTGRegister) {
        if x86High(operand) != 0 {
            out.Byte(0x41)
        }
        out.Byte(opcode + x86Low3(operand))
    }

    func x86Immediate(out *RTGEmitter, opcode byte, value uint64, width int) {
        out.Byte(opcode)
        if width == 8 {
            out.Byte(byte(value))
        } else if width == 32 {
            out.Uint32(uint32(value))
        } else {
            out.Uint64(value)
        }
    }

    func x86Relative(out *RTGEmitter, opcode uint32, label RTGLabel) {
        x86Opcode(out, opcode)
        out.Rel32(label)
    }

    func x86SetCondition(
        out *RTGEmitter,
        condition RTGCondition,
        destination RTGRegister,
    ) {
        x86REX(out, false, RTGNoRegister, RTGNoRegister, destination, destination)
        out.Byte(0x0f)
        out.Byte(condition.SetOpcode)
        x86ModRM(out, 3, 0, x86Low3(destination))
    }

    func x86JumpCondition(
        out *RTGEmitter,
        condition RTGCondition,
        label RTGLabel,
    ) {
        out.Byte(0x0f)
        out.Byte(condition.JumpOpcode)
        out.Rel32(label)
    }

    func x86MoveImmediate(out *RTGEmitter, destination RTGRegister, value int64) {
        if destination == x86RAX && value == 0 {
            out.Byte(0x31)
            out.Byte(0xc0)
        } else if destination != x86RSP && RTGSignedFits(value, 8) {
            x86Immediate(out, 0x6a, uint64(value), 8)
            x86OpcodeRegister(out, 0x58, destination)
        } else if RTGUnsignedFits(value, 32) {
            x86OpcodeRegister(out, 0xb8, destination)
            out.Uint32(uint32(value))
        } else if RTGSignedFits(value, 32) {
            x86Immediate(out, 0x68, uint64(value), 32)
            x86OpcodeRegister(out, 0x58, destination)
        } else {
            x86REX(out, true, RTGNoRegister, RTGNoRegister, destination, RTGNoRegister)
            out.Byte(0xb8 + x86Low3(destination))
            out.Uint64(uint64(value))
        }
    }

    func x86RelaxJump(displacement int64) (byte, bool) {
        return 0xeb, RTGSignedFits(displacement, 8)
    }

    func x86RelaxCondition(condition RTGCondition, displacement int64) (byte, bool) {
        return condition.JumpOpcode - 0x10, RTGSignedFits(displacement, 8)
    }

    func x86VariableShift(
        out *RTGEmitter,
        direction RTGShiftDirection,
        signed bool,
    ) {
        x86Xchg64(out, x86Primary, x86Tertiary)
        if direction == RTGShiftLeft {
            x86ShlCL64(out, x86Primary)
        } else if signed {
            x86SarCL64(out, x86Primary)
        } else {
            x86ShrCL64(out, x86Primary)
        }
    }

    func x86SignedDivide(out *RTGEmitter, remainder bool) {
        ordinary := out.NewLabel()
        done := out.NewLabel()
        x86CmpImmediate64(out, x86Primary, -1)
        x86JumpCondition(out, x86NE, ordinary)
        x86MoveImmediate(out, x86Secondary, 1)
        x86ShlImmediate64(out, x86Secondary, 63)
        x86Cmp64(out, x86Tertiary, x86Secondary)
        x86JumpCondition(out, x86NE, ordinary)
        if remainder {
            x86MoveImmediate(out, x86Primary, 0)
        } else {
            x86Mov64(out, x86Primary, x86Tertiary)
        }
        x86Relative(out, 0xe9, done)
        out.Mark(ordinary)
        x86PushRegister(out, x86DivisionScratch)
        x86Mov64(out, x86DivisionScratch, x86Primary)
        x86Mov64(out, x86Primary, x86Tertiary)
        out.Byte(0x48)
        out.Byte(0x99)
        x86Group(out, 0xf7, 7, x86DivisionScratch, 64)
        if remainder {
            x86Mov64(out, x86Primary, x86Secondary)
        }
        x86PopRegister(out, x86DivisionScratch)
        out.Mark(done)
    }

    func x86CopyBytes(out *RTGEmitter) {
        destination := x86CopyDestination
        source := x86CopySource
        count := x86CopyCount
        forward := out.NewLabel()
        done := out.NewLabel()
        x86Cmp64(out, destination, source)
        x86JumpCondition(out, x86ULE, forward)
        x86Lea64(out, x86Scratch, RTGAddress{Base: source, Index: count, Scale: 1})
        x86Cmp64(out, destination, x86Scratch)
        x86JumpCondition(out, x86UGE, forward)
        x86Lea64(out, source, RTGAddress{
            Base: source, Index: count, Scale: 1, Displacement: -1,
        })
        x86Lea64(out, destination, RTGAddress{
            Base: destination, Index: count, Scale: 1, Displacement: -1,
        })
        out.Byte(0xfd)
        out.Byte(0xf3)
        out.Byte(0xa4)
        out.Byte(0xfc)
        x86Relative(out, 0xe9, done)
        out.Mark(forward)
        out.Byte(0xfc)
        out.Byte(0xf3)
        out.Byte(0xa4)
        out.Mark(done)
    }

    func windowsCommandLine(command []byte) [][]byte {
        arguments := make([][]byte, 0, 8)
        offset := 0
        for offset < len(command) {
            for offset < len(command) &&
                (command[offset] == ' ' || command[offset] == '\t') {
                offset++
            }
            if offset == len(command) {
                break
            }

            argument := make([]byte, 0, 32)
            quoted := false
            for offset < len(command) {
                if !quoted &&
                    (command[offset] == ' ' || command[offset] == '\t') {
                    break
                }
                if command[offset] == '"' {
                    quoted = !quoted
                    offset++
                    continue
                }
                if command[offset] != '\\' {
                    argument = append(argument, command[offset])
                    offset++
                    continue
                }

                slashStart := offset
                for offset < len(command) && command[offset] == '\\' {
                    offset++
                }
                slashCount := offset - slashStart
                if offset == len(command) || command[offset] != '"' {
                    for slashCount > 0 {
                        argument = append(argument, '\\')
                        slashCount--
                    }
                    continue
                }

                for slashCount >= 2 {
                    argument = append(argument, '\\')
                    slashCount -= 2
                }
                if slashCount == 1 {
                    argument = append(argument, '"')
                    offset++
                } else {
                    quoted = !quoted
                    offset++
                }
            }
            arguments = append(arguments, argument)
        }
        return arguments
    }
}

arch x86_64 {
    alias = "amd64"
    endian = little
    word_bits = 64
    pointer_bits = 64
    instruction_alignment = 1
    stack_word_bytes = 8
    stack_alignment = 16
    unaligned_memory = true

    # List position is the architectural register number. The x86 encoder
    # derives low3, REX bits, byte-register names, RSP/R12 SIB rules, and
    # RBP/R13 displacement rules from this single list.
    registers gpr64 = [
        rax, rcx, rdx, rbx, rsp, rbp, rsi, rdi,
        r8, r9, r10, r11, r12, r13, r14, r15
    ]

    locations {
        primary = rax
        secondary = rdx
        tertiary = rcx
        scratch = r10
        division_scratch = rbx
        copy_destination = rdi
        copy_source = rsi
        copy_count = rcx
        stack = rsp
        frame = rbp
    }

    # One row supplies both SETcc and near Jcc. Unsigned conditions no longer
    # need separate hand-written lowering functions.
    conditions {
        eq  0x94 0x84
        ne  0x95 0x85
        slt 0x9c 0x8c
        sge 0x9d 0x8d
        sle 0x9e 0x8e
        sgt 0x9f 0x8f
        ult 0x92 0x82
        uge 0x93 0x83
        ule 0x96 0x86
        ugt 0x97 0x87
    }

    # Width and extension policy is stated once per source-language scalar.
    scalars {
        zero_extend { bool:1 byte:1 uint16:2 uint32:4 }
        sign_extend { int8:1 int16:2 int32:4 }
        native { int:8 int64:8 uint64:8 pointer:8 }
    }

    # Form names are declarative aliases for ordinary Go functions above.
    # A row is specialized into a direct call with its opcode, width, and
    # selector constants; there is no function registry in the result.
    forms {
        rr_rm         = go x86RRRM
        rr            = go x86RR
        rm_r          = go x86RMR
        r_rm          = go x86RRM
        group         = go x86Group
        group_imm     = go x86GroupImmediate
        group_imm8    = go x86GroupImmediate8
        group_mem_imm = go x86GroupMemoryImmediate
        imul_imm      = go x86MultiplyImmediate
        opcode_reg    = go x86OpcodeRegister
        immediate     = go x86Immediate
        relative      = go x86Relative
        set_condition = go x86SetCondition
        jump_condition = go x86JumpCondition
        fixed         = bytes
    }

    # Every row is: generated name, form, opcode, and optional group selector.
    instructions {
        mov64       rr_rm       0x89
        load64      rm_r        0x8b
        lea64       rm_r        0x8d
        load_i32    rm_r        0x63
        load_u32    rm_r        0x8b width=32
        load_i16    rm_r        0x0fbf
        load_u16    rm_r        0x0fb7
        load_i8     rm_r        0x0fbe
        load_u8     rm_r        0x0fb6
        store64     r_rm        0x89
        store32     r_rm        0x89 width=32
        store16     r_rm        0x89 width=16
        store8      r_rm        0x88 width=8

        add64       rr_rm       0x01
        sub64       rr_rm       0x29
        and64       rr_rm       0x21
        or64        rr_rm       0x09
        xor64       rr_rm       0x31
        cmp64       rr_rm       0x39
        test64      rr_rm       0x85
        imul64      rr          0x0faf
        xchg64      rr_rm       0x87

        add_imm64   group_imm   0x81 /0
        or_imm64    group_imm   0x81 /1
        and_imm64   group_imm   0x81 /4
        sub_imm64   group_imm   0x81 /5
        xor_imm64   group_imm   0x81 /6
        cmp_imm64   group_imm   0x81 /7
        cmp_mem_imm64 group_mem_imm 0x81 /7
        imul_imm64  imul_imm    0x69

        inc64       group       0xff /0
        dec64       group       0xff /1
        shl_imm64   group_imm8  0xc1 /4
        shr_imm64   group_imm8  0xc1 /5
        sar_imm64   group_imm8  0xc1 /7
        shl_cl64    group       0xd3 /4
        shr_cl64    group       0xd3 /5
        sar_cl64    group       0xd3 /7
        call_reg    group       0xff /2
        idiv64      group       0xf7 /7

        push_reg    opcode_reg  0x50
        pop_reg     opcode_reg  0x58
        push_imm8   immediate   0x6a width=8
        push_imm32  immediate   0x68 width=32
        setcc       set_condition
        jcc_rel32   jump_condition relocation=rel32
        call_rel32  relative    0xe8 relocation=rel32
        jump_rel32  relative    0xe9 relocation=rel32

        ret         fixed       [0xc3]
        leave       fixed       [0xc9]
        syscall     fixed       [0x0f, 0x05]
        cqo         fixed       [0x48, 0x99]
        cld         fixed       [0xfc]
        std         fixed       [0xfd]
        rep_movsb   fixed       [0xf3, 0xa4]
    }

    # The shared IR uses parameterized operations such as move(dst, src),
    # load(dst, address, kind), and compare(left, right, condition). These
    # bindings select x86 instruction families once; role-specific wrappers
    # are generated after primary/secondary/tertiary are known.
    bind {
        move = mov64
        address = lea64
        load.native = load64
        load.i32 = load_i32
        load.u32 = load_u32
        load.i16 = load_i16
        load.u16 = load_u16
        load.i8 = load_i8
        load.u8 = load_u8
        store.native = store64
        store.u32 = store32
        store.u16 = store16
        store.u8 = store8

        add = add64
        subtract = sub64
        multiply = imul64
        bit_and = and64
        bit_or = or64
        bit_xor = xor64
        compare = cmp64
        test = test64
        increment = inc64
        decrement = dec64
        shift_left_immediate = shl_imm64
        shift_right_unsigned_immediate = shr_imm64
        shift_right_signed_immediate = sar_imm64

        call = call_rel32
        call_indirect = call_reg
        jump = jump_rel32
        jump_condition = jcc_rel32
        set_condition = setcc
        return = ret
        leave = leave
        host_syscall = syscall
        move_immediate = go x86MoveImmediate
        variable_shift = go x86VariableShift
        signed_divide = go x86SignedDivide
        copy_bytes = go x86CopyBytes
    }

    relax {
        jump_rel32 to jump_rel8 = go x86RelaxJump
        jcc_rel32 to jcc_rel8 = go x86RelaxCondition
    }

    relocation rel32 {
        width = 4
        signed = true
        relative_to = field_end
        kinds = [label, data, bss, import]
    }

    frame {
        base = rbp
        stack = rsp
        alignment = 16
        maximum = 65520
        prologue = [0xc8, frame_size:u16le, 0x00]
        epilogue = [leave, ret]
        overflow_arguments = rbp + 16
    }

}

# Image fields are declared here. Header/section/relocation are generic
# definition-language constructs, not precompiled ELF or PE backends.
format elf64_x86_64 {
    byte_order = little
    address_bits = 64
    file_alignment = 0x1000
    machine = 62

    header elf {
        magic = [0x7f, 0x45, 0x4c, 0x46]
        class = 2
        data = 1
        version = 1
        osabi = 0
        type = 3
        machine = 62
        entry = address(text.start)
        program_header_offset = sizeof(elf_header)
        section_header_offset = stripped ? 0 : sections.offset
        flags = 0
        elf_header_size = 64
        program_header_size = 56
        program_header_count = 2
        section_header_size = stripped ? 0 : 64
        section_header_count = stripped ? 0 : sections.count
        section_name_index = stripped ? 0 : sections.names
    }

    segment text {
        type = load
        flags = read | execute
        file = [headers.start, data.file_start)
        memory = [headers.start, data.memory_start)
        alignment = 0x1000
    }

    segment data {
        type = load
        flags = read | write
        file = [data.file_start, data.file_end)
        memory = [data.memory_start, bss.end)
        alignment = 0x1000
    }

    sections when !stripped {
        text progbits alloc|execute align=16
        data progbits alloc|write align=8
        bss nobits alloc|write align=8
        symtab symtab entry_size=24 link=strtab
        strtab strtab
        shstrtab strtab
    }

    relocation {
        label = rel32
        data = rel32
        bss = rel32
    }
}

        data progbits alloc|write align=8

}

format pe64_x86_64 {
    byte_order = little
    address_bits = 64
    machine = 0x8664
    image_base = 0x400000
    headers_size = 0x200
    file_alignment = 0x200
    section_alignment = 0x1000
    text_rva = 0x1000

    dos_header {
        magic = [0x4d, 0x5a]
        pe_offset = 0x80
    }

    coff_header {
        machine = 0x8664
        sections = 2
        optional_header_size = 0xf0
        characteristics = executable | large_address_aware
    }

    optional_header {
        magic = 0x20b
        entry = rva(text.start)
        code_base = rva(text.start)
        image_base = 0x400000
        section_alignment = 0x1000
        file_alignment = 0x200
        subsystem = target.subsystem
        stack_reserve = 8MiB
        stack_commit = 4KiB
        heap_reserve = 1MiB
        directories = [imports.directory, imports.iat]
    }

        name = ".text"
        flags = code | execute | read
        virtual = text
        raw_alignment = 0x200
    }

    section data {
        name = ".data"
        flags = initialized_data | read | write
        virtual = data + bss
        raw = data
        raw_alignment = 0x200
    }

    imports {
        thunk_bytes = 8
        library = "KERNEL32.dll"
        names = target.runtime.imports

        descriptor size=20 {

            u32 timestamp = 0
            u32 forwarder_chain = 0
            u32 name = rva(library_name)

        }

        import_lookup_table {
            entries names as u64 rva(hint_name(entry))
            terminator = u64 0
        }

        import_address_table {
            entries names as u64 rva(hint_name(entry))
            terminator = u64 0
        }

        hint_name(entry) {
            u16 0
            ascii entry
            u8 0
            align 2
        }

        library_name {
            ascii library
            u8 0
        }

        directory.rva = rva(descriptor)
        directory.size = sizeof(descriptor)
        iat.rva = rva(import_address_table)
        iat.size = sizeof(import_address_table)
    }

    relocation import = rel32 from instruction_end to imports.iat_entry
    relocation data = rel32 from instruction_end to data
    relocation bss = rel32 from instruction_end to bss
}

format coff64_object_x86_64 {
    byte_order = little
    address_bits = 64

Why this stays KISS and DRY

  • Register numbers, scalar widths, conditions, opcodes, and operation bindings each have one source of truth.
  • The file does not repeat primary/secondary/tertiary combinations; the generator specializes the built-in versioned IR vocabulary after reading the location map.
  • Architecture-neutral string, slice, stack, comparison, and control-flow composites belong to the built-in IR contract, not to imported target files.
  • ModRM, SIB, REX, displacement, immediate, branch relaxation, division, copying, and Windows argument parsing are ordinary Go functions near the top of this closed file.
  • Tables and image layouts use bounded schema expressions, not a macro language. User-defined control flow belongs in embedded Go.
  • Exceptional x86 behavior is readable Go. There is no rewrite DSL, external encoder, or OS hook hiding the implementation.
  • Linux, Windows, and kernel-module targets reuse named ISA, ABI, runtime, and format declarations within the same file. Future UEFI, Darwin, BSD, illumos, and Plan 9 x86-64 work from issue #24 extends this authority instead of forking the ISA.
  • Instruction forms are tested at the encoder boundary with ordinary Go tests rather than another test syntax inside .rtg.

What the generator produces

  • One direct Go function for every bound IR operation, with parameterized locations and composite lowerings specialized into ordinary calls and conditionals.
  • The embedded ModRM/SIB/REX, immediate-selection, branch-relaxation, division, copying, and argument-parsing functions as ordinary package declarations—not quoted source or callbacks.
  • No register-name lookup, definition AST, string property lookup, recipe dispatch, or target switch in the generated compiler.
  • A completeness table generated from ir.direct_emitter_v1, failing generation if any operation, width, relocation, or target capability is missing.
  • Separate fixed-target compositions so a Linux compiler does not retain PE/Win32 code and a Windows compiler does not retain ELF/Linux code.

For example, the add64 row does not survive as data. After names and constants are resolved, the emitted Go contains a normal wrapper beside the parsed body of x86RRRM: 

package backend

// Local x86RRRM is emitted with the unit prefix.
func rtgX8664X86RRRM(
    out *RTGEmitter,
    opcode uint32,
    destination RTGRegister,
    source RTGRegister,
    width int,
) {
    if width == 16 {
        out.Byte(0x66)
    }
    byteRegister := RTGNoRegister
    if width == 8 {
        byteRegister = source
    }
    rtgX8664X86REX(out, width == 64, source, RTGNoRegister, destination, byteRegister)
    rtgX8664X86Opcode(out, opcode)
    rtgX8664X86ModRM(
        out, 3, rtgX8664X86Low3(source), rtgX8664X86Low3(destination),
    )
}

// Generated from: add64 rr_rm 0x01
func rtgX8664X86Add64(
    out *RTGEmitter,
    destination RTGRegister,
    source RTGRegister,
) {
    rtgX8664X86RRRM(out, 0x01, destination, source, 64)
}

Fixed-target pruning starts from wrappers such as rtgX8664X86Add64. Ordinary Go reachability then removes unused embedded declarations and all unselected target compositions.

  1. Regenerate all checked-in backend outputs and confirm a clean worktree.
  2. Run definition parser, validator, generator, malformed-input, determinism, and stale-output tests.
  3. Run the full backend suite for every advertised native, Wasm, and VM target with unchanged gates.
  4. Run the full frontend suite and full bundled self-hosting suite.
  5. Build prepared backends from source definitions through Renvo on Linux, Darwin, and Windows hosts where available.
  6. Compile with both cold preparation and warm cache hits and compare outputs.
  7. Use a prepared backend for a target unknown to the invoking compiler and produce a valid target image.
  8. Reject mismatched RTGU, definition, schema, protocol, host, and corrupt artifact cases.
  9. Measure and record backend-core, cold, warm, size, and peak-memory results.
