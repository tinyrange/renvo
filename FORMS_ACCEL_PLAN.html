Fully accelerated Forms rendering

A dual-path rendering design that lets Forms paint the same way into a tiny software framebuffer or a retained GPU target—without turning Surface.Pixels into a misleading compatibility trap.

Proposed macOS only Metal first OpenGL conformance Software preserved No generics

Prepared for tinyrange/renvo#345 · 11 August 2026

Decision

Make drawing polymorphic; keep pixel storage concrete. Add a composed graphics.Canvas interface. *graphics.Surface remains the CPU-backed implementation and continues to own public pixels. A new unexported *gpuCanvas implements the same drawing contract by producing a compact, backend-neutral draw list. Forms paint handlers move from func(*graphics.Surface) to func(graphics.Canvas).
Initial platform scope: macOS only. This work delivers and validates Metal and OpenGL acceleration on macOS. iOS and Android integration belong in later PRs after the Canvas contract and draw-list behavior have stabilized. The shared interfaces should permit those ports, but this PR must not add their native backends or make mobile testing a merge requirement.

This is a purposeful source migration, not a cosmetic abstraction. A GPU target cannot safely masquerade as the current Surface: direct writes to the exported Pixels slice cannot be observed, and GPU drawing cannot cheaply keep that slice current. The interface puts the seam at the operation boundary, where both implementations have honest semantics.

Forms widgets
paint to graphics.Canvas
Software lane

*Surface immediately rasterizes into premultiplied RGBA8 or A8 pixels. Native display, browser upload, image export, and microcontroller display continue to consume those pixels.

Accelerated lane

*gpuCanvas transforms and encodes geometry, image, text, clip, and blend commands. Metal or OpenGL renders them into a persistent texture, then presents it.

Why this boundary

1

One widget implementation

Controls keep calling familiar drawing methods. They do not import Metal, OpenGL, shaders, or platform types.

2

No per-pixel interface cost

The software implementation enters a concrete *Surface method once per primitive; its inner pixel loops remain direct calls.

3

Truthful resource semantics

Surface always means CPU pixels. A GPU canvas has no exported fake framebuffer and readback stays explicit.

Constraints and invariants

Must remain true

  • Software rendering remains a first-class renderer, not a fallback shim.
  • Microcontrollers can use NewSurface with no GPU code, native handles, or command-list allocation.
  • Coordinates stay upper-left, half-open, and device-scale aware.
  • RGBA8 remains premultiplied; BlendCopy and source-over remain deterministic contracts.
  • Forms damage rectangles retain unchanged pixels between frames.
  • The ordinary Go headless renderer remains the pixel-correctness oracle.
  • Renvo builds use no cgo or third-party runtime dependency.

Deliberately out of scope

  • A scene graph or retained widget display list across frames.
  • Replacing Forms layout, event dispatch, or invalidation.
  • iOS or Android accelerated backends, native layer integration, and device validation.
  • Subpixel LCD text, HDR, color management, perspective, or arbitrary clip paths.
  • Making raw Surface.Pixels writes automatically uploadable.
  • Introducing generics, goroutines, channels, reflection, or any-based command payloads.
Compiler constraints shape the Go design. Renvo intentionally excludes generics, goroutines, and channels. Use explicit structs, typed enums, interface composition, embedding, and build-tag-selected factories. Keep hot data homogeneous and avoid interface values inside command arrays so lowering stays simple and predictable.

Proposed architecture

There are three stable layers. Each owns one kind of variability:

  1. Canvas contract: portable drawing semantics shared by widgets and applications.
  2. GPU draw-list encoder: shared transforms, tessellation, batching decisions, image references, and validation.
  3. Render backend: native resource creation and execution for Metal or OpenGL.

The software path implements layer 1 directly and bypasses layers 2 and 3. This is intentional. Forcing software through a GPU-shaped command list would add allocations and latency to the smallest targets while making the existing optimized pixel routines harder to reason about.

The draw list is per frame, not retained UI state. Forms remains the source of truth. Only pixels in the persistent render target survive between frames. This preserves current invalidation semantics and avoids cache invalidation bugs when application paint callbacks depend on mutable state.

Frame ownership

A concrete frame type makes begin/present pairing explicit without adding another large public interface. Existing immediate-mode window callers keep Surface() and Present(); Forms uses the frame API.

type Frame struct {
	window  *Window
	canvas  Canvas
	backend frameBackend
	ended   bool
}

func (w *Window) BeginFrame() *Frame
func (f *Frame) Canvas() Canvas
func (f *Frame) Present() bool
func (f *Frame) Cancel()

func (a *App) paint() bool {
	if len(a.Form.invalid) == 0 {
		return true
	}
	frame := a.Window.BeginFrame()
	if frame == nil {
		return false
	}
	if !a.Form.Paint(frame.Canvas()) {
		frame.Cancel()
		return true
	}
	return frame.Present()
}

Frame prevents accidental double presentation and gives timing instrumentation a natural lifetime. Window.Present remains a compatibility wrapper for the software surface path, but GPU Forms code never depends on Window.Surface().

Backend contract

Keep the platform interface narrow. It receives already-normalized work; it does not know about Forms controls, paths, fonts, or affine stacks.

type frameConfig struct {
	width, height int       // physical pixels
	damage        []pixelRect
	clear         bool      // true after create/resize/context loss
}

type frameBackend interface {
	Begin(frameConfig) bool
	Render(*drawList) bool
	Present() bool
	Resize(width, height int) bool
	ReadPixels(*Surface) bool
	Destroy()
	Stats() RenderStats
}

var _ frameBackend = (*metalBackend)(nil)
var _ frameBackend = (*openGLBackend)(nil)

Do not expose native device, queue, texture, or context handles through this interface. Backend-specific helper types can use embedding for shared lifecycle state, while capability differences are handled during backend construction rather than with type assertions in the paint loop.

Typed command model

The GPU canvas owns reusable slices for vertices, commands, damage, and image references. Reset slice lengths at frame start and retain capacity. Commands contain only scalar values and integer indices—never any, reflection metadata, closures, or per-command interface values.

func (l *drawList) Reset() {
	l.vertices = l.vertices[:0]
	l.commands = l.commands[:0]
	l.images = l.images[:0]
	l.paths = l.paths[:0]
}

Batching rule

Preserve painter order. Merge only adjacent commands with identical pipeline, blend, texture, sampling, and clip state. This captures the common Forms case—many neighboring solid rectangles or glyphs—without reordering translucent controls.

Normalize on the CPU

Apply the complete affine transform and device scale before appending vertices. Convert upper-left coordinates to backend viewport coordinates in one shared place. Backends receive physical-pixel geometry and identical scissor rectangles.

Execute on the GPU

Upload growing vertex ranges through a reusable ring buffer, bind the small pipeline set, resolve images through the texture cache, set scissor/blend state, and draw.

Encoding CPU geometry is still “fully accelerated” in the useful sense: expensive coverage, sampling, tinting, blending, and framebuffer writes move to the GPU. Keeping portable tessellation above the backend also prevents Metal and OpenGL from slowly diverging.

Path filling

Path already flattens quadratic and cubic curves into portable line contours. Reuse those contours. For a fill command, render signed contour fans or edge wedges into an 8-bit stencil attachment, using invert for even-odd and increment/decrement wrapping for non-zero winding. Then draw the path bounds where the stencil test passes and clear only that stencil rectangle.

Keep the existing software point-in-path rasterizer as the exact fallback. A later optimization may add a robust tessellator for simple contours, but it is not a prerequisite for correctness.

Text

  1. Keep TrueType parsing, kerning, layout, and A8 glyph rasterization in shared Go code.
  2. Pack generated masks into renderer-owned A8 atlas pages. Store atlas coordinates beside the renderer cache entry, not in Font, because a font may be drawn by multiple windows or backends.
  3. Emit glyph quads in text order; batch adjacent glyphs on the same atlas page and clip.
  4. Use nearest sampling for integer-scaled built-in glyphs and linear sampling for TrueType masks when transformed.
First milestone can skip atlas packing. Uploading one immutable texture per cached glyph proves the interface and shader semantics. Add the atlas before calling the work performance-complete, not before the first pixel-correct Metal frame.

Frame lifecycle and damage

Damage-scoped repainting requires persistent GPU storage. A swapchain or CAMetalLayer drawable is not guaranteed to preserve old pixels, so Forms must never paint partial damage directly into the drawable.

BeginFrameacquire encoder; reset draw list
Form.Paintrecord commands inside damage clips
Persistent textureupdate only damaged regions
Drawable passone full-screen copy or quad
Presentcommit and publish timings
  • Create one private RGBA8 render target and stencil attachment per window at physical pixel size.
  • On create, resize, scale change, context loss, or backend switch, invalidate the whole target and require a full Forms repaint.
  • BeginDamage records the exact transformed region and intersects the active scissor. Nested damage stays balanced.
  • Each command is clipped by both the Forms damage clip and the canvas clip stack, so commands for one invalid region cannot touch preserved pixels in another.
  • The final pass copies the persistent target to the current drawable. Start with a full copy; optimize partial platform presents only after measurement.
  • If no drawable is available, cancel without clearing Forms invalidation. Never reset damage merely because command submission failed.

Implementation order

Build Metal first on macOS because the development machine can test it directly and Metal is the long-term Apple API. Keep device, queue, pipeline, resource, and shader logic separate from Cocoa window lifecycle so a later iOS PR can reuse the portable pieces without making iOS part of this implementation. Then implement macOS OpenGL against the exact same draw-list conformance tests.

OpenGL should use a shader-capable profile and FBOs. The existing glDrawPixels path remains a software-presentation fallback; it is not the accelerated backend. On platforms where only the legacy API is available, RendererAuto should select software instead of claiming acceleration.

Keep native ABI work narrow. Metal calls still cross Renvo’s Objective-C/runtime boundary. Isolate selector declarations, structure layouts, and native handle management in target files. The shared encoder must be ordinary Go that the host test suite can exercise without a GPU.

Software rendering remains the reference path

The software renderer should become cleaner as a result of this work, not more conditional:

  • Surface continues to allocate only its pixel storage and existing state slices.
  • Its methods stay concrete and invoke concrete helpers such as fillPixelRect and putPixel.
  • No backend interface is stored on Surface; no nil check is added to every primitive; no draw list is created.
  • Direct pixel access, offscreen drawing, PPM export, the browser path, and microcontroller display code remain valid.
  • Target build tags prevent Metal/OpenGL source from entering small target compilation units. Bundled source size is still measured separately.
// A display-oriented microcontroller program is unchanged.
surface := graphics.NewSurface(width, height)
surface.FillRect(graphics.R(0, 0, width, height), background)
drawDashboard(surface) // *Surface implicitly satisfies Canvas if desired
display.Present(surface.Pixels, surface.Stride)

Where interface dispatch matters on a small target, application helpers may continue accepting *Surface. Forms uses Canvas because it needs polymorphism; the graphics package does not force every caller through it.

Migration plan

Introduce Canvas without behavior change

Add the composed interfaces and compile-time assertions. Mechanically migrate Forms widgets, IDE paint callbacks, examples, generator output, and tests to graphics.Canvas. Keep Form.PaintSurface(*Surface) as a short-lived compatibility helper if downstream migration needs staging.

Exit: all existing software screenshots and package tests are unchanged.

Build and test the portable GPU encoder

Add gpuCanvas, draw-list structs, geometry builders, state normalization, command recorder tests, and a fake backend. Cover every Canvas method before native code.

Exit: Forms controls produce valid, bounded commands with correct ordering, clips, transforms, damage, and image references.

Render Metal on macOS

Implement solid and textured pipelines, persistent target, scissor, blending, resize, readback, and frame stats. Start with rectangles/images, then lines/ellipses, text masks, and stencil paths.

Exit: the Forms controls demo and IDE render completely without CPU framebuffer rasterization.

Add the macOS OpenGL conformance backend

Implement shaders, VBO, FBO, textures, stencil, readback, and truthful timing availability in the macOS window path. Use the same draw lists and parity scenes.

Exit: switching between Metal, OpenGL, and software on macOS changes no Forms layout or drawing behavior within defined raster tolerance.

Optimize measured bottlenecks

Add glyph atlas pages, adjacent-command batching, reusable upload rings, texture damage uploads, and cache eviction. Measure before adding complexity.

Exit: target latency and frame-time goals pass without regressing software size or speed gates.

Recommended PR shape. Keep the Canvas migration and portable encoder reviewable independently from native Metal ABI work. The issue can be delivered as a short stack of mergeable PRs rather than one platform-heavy change whose type design is difficult to revise.

Canonical parity scene

Build one deterministic scene covering opaque and translucent rectangles, transformed lines, clipped ellipses, both path rules with holes, nearest and linear image scaling, tinted RGBA/A8 images, built-in text, TrueType text, overlapping popups, and multiple disjoint damage rectangles. Exact comparison is required away from antialiased coverage edges. At defined edges, allow a small per-channel tolerance and a bounded number of differing pixels; record that policy in the test rather than broadly weakening comparisons.

Highest implementation risks

  1. Raster parity: GPU edge rules, sampler coordinates, premultiplication, and winding must match the portable contract closely enough that widgets do not shimmer or shift.
  2. Native ABI surface: Metal expands Objective-C/runtime calls and native struct handling. Keep it isolated and test basic resource calls before building the full renderer.
  3. Frontend/code-size pressure: interfaces, shader strings, and target sources affect compilation or bundled-source size. Run the real system profile throughout, not only at the end.
  4. Lifecycle correctness: resize, scale, hide/show, drawable starvation, and context loss must retain or invalidate Forms damage consistently.

Merge criteria for the completed issue

  • Forms paint handlers use graphics.Canvas; all built-in widgets render through both implementations.
  • *graphics.Surface remains a pixel-backed, independently tested software renderer with no GPU dependency or per-pixel interface dispatch.
  • Metal rendering on macOS covers every Canvas primitive used by Forms, including text, images, transforms, clipping, blend modes, and both path fill rules.
  • macOS OpenGL implements the same draw-list contract where its required profile is available; legacy software presentation remains a valid fallback.
  • Partial damage preserves all pixels outside invalid regions through multiple frames and resize forces full repaint.
  • ReadPixels, debug timing, backend failure, and explicit renderer selection have documented, tested semantics.
  • The canonical Metal and OpenGL readbacks pass software parity tests on the development Mac at each available backing scale.
  • iOS and Android continue using their existing rendering paths; neither mobile acceleration nor device testing is required by this PR.
  • No regression in microcontroller software rendering, browser presentation, frontend self-hosting, performance/resource gates, or the 2 MiB bundled frontend limit.
  • ./tools/check preflight and ./tools/check full pass without weakening any gate.
Suggested first implementation slice Land the Canvas migration plus a host-testable GPU command recorder and fake backend. It proves the architectural seam, exercises Renvo interface dispatch, and exposes command/state mistakes before Metal ABI and shader work make changes expensive.
